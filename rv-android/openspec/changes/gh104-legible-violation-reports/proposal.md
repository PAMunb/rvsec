## Why

GitHub Issue: #104

RVSEC's violation reports cannot be read. In the published dataset 72.93 % of the 97,018 records carry the literal `unknown` as their message (70,760 rows, 19 distinct messages in the whole corpus) and 8,843 more read `but found .` with an empty observed value; the post-repair Study-03 trial (`experimento-comp162`, 19,664 rows) is worse in the first ratio at 79.91 %. The mechanical cause is measured and small — `message == 'unknown'` if and only if the report site used the three-argument `ErrorDescription` constructor (`ErrorDescription.java:34-36`), which is 25 of the 51 report sites of the `jca` set — but three families of defects around it turn readable reports into wrong ones: the dexlib2 weaver ignores positional `args()` arity when it merges advices into one wrapper (a residue of gh100's D-B1 merge that gh100 does not record); the transport path from `ErrorCollector` to `errors.csv` escapes nothing, fabricates fields and drops lines silently at ten points; and the `jca` automata carry 18 events that accuse unconditionally, 15 messages whose text contradicts the guarding condition or the real allow-list, and structural defects nobody catalogued. Because the `@fail` handler names neither the offending event nor the observed value, and the dedupe identity (`ErrorSummary` = spec, error, class, method, location) discards exactly the information the message would carry, per-event attribution is impossible today for any consumer of the record — including the analyses this thesis publishes.

`jca` is frozen (gh101 D-S0, `INV-INS-109`) and `jca_android` was judged NOT READY (audit 2026-08-08). This change therefore lands every specification-side repair in a **successor set `jca_v2` derived byte-for-byte from the frozen `jca`**, and every runtime, weaver and transport repair in the shared code both sets execute on. The `generic` and `generic_new` sets (145 of the 191 `.mop` files, none of which passes through `ErrorCollector`) are a written non-goal.

## What Changes

- **New specification set `jca_v2`** under `rvsec-mop/src/main/resources/jca_v2/`, seeded byte-identical from the frozen `jca`, selectable by name (`--specification-set jca_v2`), with its own divergence record and conformance record in `data/jca_v2/`; the frozen `jca` and its freeze gate stay untouched. Oracle rule for the new set: MetaCrySL api30 for availability (Cipher catalogue, keystore types), CrySL 1.5.2 for recommendation (digests, protocols), recorded per specification, never mixed silently.
- **Event name from the generator (G)**: `rv-monitor` gains a `__EVENTNAME` macro — expanded to a string literal inside an event body, and inside a `@fail` handler to the name of the event that last transitioned the monitor. This is information the generated monitor already holds and throws away: it packs the event index into `pairValue` (or keeps it in `RVM_lastevent`), and the generator writes the matching names as *comments* in `terminateInternal`. Emitting them as a table costs two substitution sites and one array, instead of 134 hand-written bookkeeping lines per specification set, and it cannot produce a wrong name because the table and the indices come from one iteration. The freeze is on the specification sources, not on generated monitors — published measurements reproduce by pinning the toolchain.
- **Legible messages (E1)**: every one of the 25 three-argument report sites of the set receives a fourth argument; the 17 `but found` sites interpolate the event argument instead of a monitor field; the 15 messages whose text lies (numeric literals off by a factor of ten, `ErrorType` that does not match the test, expected lists with half the real entries, missing spaces and verbs) are corrected as a precondition; every envelope takes its `ev=` from `__EVENTNAME`. Message envelope grammar v1: `v=1 code=<SPEC>-<KIND>-<NN> ev=<event> obj=<SimpleClass> val='<observed>' exp='<expected>' msg='<text>'` — no `st=`, no `\n`, no `:::` inside values; commas allowed (the parser rejoins field 7).
- **Weaver `args()` arity (E2)**: when `WrapperEmitter` groups advices into one merged wrapper it enforces positional arity with the three-clause rule — an advice with no `args()` clause is never filtered; the arity is read from `ArgsPC.types()` (so `..` is honoured); the filter runs in the grouping loop where the concrete overload's parameter count is known — and counts the advices it excludes into the results JSON. Its reach is partial and declared: the grouping loop admits only `after` advices and skips constructors, so of the frozen descriptor's 71 advices with `args()` the rule covers 48 and leaves 9 `before` and 14 `after`-on-constructor unfiltered, all named in the delta. Closing those at the root is the binding-form check in `PointcutMatcher`, recorded as future work.
- **Honest transport (E3)**: the logcat `ErrorCollector` escapes the message and guards `null`; the CSV collector and the logcat collector agree; `logcat_parser` counts every discarded or continuation line, replaces fabricated fields with explicit sentinels (`error_type=UNSPECIFIED`, `source=UNSPECIFIED:0`), treats an unclosed quote as a truncated record, and no longer scrambles a Format-1 line whose regex fails into the comma path; `unique_msg` is built in exactly one place; the `ViolationRecorder` frame filter no longer lets a monitor frame with a `null` file name become the reported location. **BREAKING** for consumers that regex the free text of `message` (`ase-journal/.../owasp_cwe_mapping_gen.py`, `experimento-gov/scripts/consolidate_gov.py`, `validator/oracles/cryptoapp-oracle.yaml`): the consumer matrix names each and its migration.
- **Validation toolkit (EV)**: the orphan-event check becomes a pytest over the generated monitor of any set (G-2), joined by the structural gates that are computable on the transition tables (G-2a inertia, G-2b′ redundancy at q0, G-2c dead states, G-2d sink is not `fail`, G-6′ event-name injectivity), a `.mop` lint (undeclared or duplicate ERE symbol, unbalanced parentheses, no hand-written event-name bookkeeping — the generator emits the name), a message-property gate (every report site four-argument, numeric literals of a message equal to those of its guard), and a **differential harness** that generates monitors from two snapshots of a set and replays the same traces through both, so a repair that moves a defect instead of removing it is seen. Gate G-2b as proposed by the lineage is not adopted: it is not computable on the artefact (minimisation merges the state it needs), and its absorbing-state repair was already rejected in gh101 D-S9.
- **Automata (E4)**: on `jca_v2`, replay of the 94 non-allow-list gh101 hunks recorded in `data/gh101/divergence_record.csv` (51 layer-2 repairs including the 18 all-`fail` events, 42 predicate-graph edges, 1 cipher-import), except the three the audit marks as introduced by gh101 (`GENCIPHER-EXTRA`, `SSL-RANDOMIZED-EXTRA`, `KPG initError` placement), plus the newly catalogued defects (`SecretKeySpecSpec` unbalanced parentheses, `GCMParameterSpecSpec` duplicate `c1` and phantom `c2`, `TrustManagerFactorySpec.gtm1` four stacked defects, `KeyPairGeneratorSpec` uninitialised `algorithm`, `SecretKeySpec` null detector, dead `SignatureSpec.sign()` and `SSLContextSpec.createSSLEngine` pointcuts, `KeyGeneratorSpec.g3` testing the field, four `remove(Property)` one-argument sites) — every edit under the 17-event generator ceiling and entered in the set's divergence record.
- **Predicates (E5)**: `ErrorType` gains `RequiredPredicate` and `ForbiddenMethod`; predicate reads move from `condition()` into event bodies with the automaton co-edited; missing producers are added or recorded as unclosable; all under the ruling that `ExecutionContext` stays equality-keyed (commit `e204e2a4` reverted gh101 D-S10 and gh101 does not record it).
- **Identity (E6)** — **BREAKING**: `ev` and `code` enter the `ErrorSummary` dedupe identity, `unique_msg` and `errors.csv` (new columns `code`, `event`); the count discontinuity against every published dedupe number is declared and measured, and it must be non-zero.
- **Baseline (E0)**: the residual budget of the E3 trial is measured through `aperv_tool.analysis.violations.read_errors_csv` and a declared separate reader for the 10-column article dataset; the definitions (mute row, site as 4-tuple on comp162 and 3-tuple on the article, the nine-prefix third-party classifier, comp162 as 8 disjoint shards) are registered as freeze items before any number is published, every number with numerator and denominator.

### Modified Capabilities

- `instrumentation`: `jca_v2` becomes a first-class specification set (INV-INS-09, Specification Set Support); the message envelope contract of a violation report and the four-argument rule for report sites; the `__EVENTNAME` macro the generator expands and the message-property gate; the weaver's `args()` arity rule for merged wrappers and its excluded-advice counter; the orphan-event and structural gates as executable pytest for any set; the differential harness; the divergence and conformance records of the successor set; the frozen `jca` requirement gains the sentence that `jca_v2` is outside the freeze.
- `experiment`: `specification_set` accepts `jca_v2` (INV-EXP-03 clause f, Just-in-Time Sub-Module Configuration).
- `analysis`: the logcat violation-line grammar (INV-ANA-08): seven comma-separated fields, message last as a `key=value` envelope; sentinels for fabricated fields; continuation and discarded lines counted; unclosed quote is a truncated record; `unique_msg` built once.
- `core`: `RvErrorLog.unique_msg` gains `code` and `event` parts (INV-CORE-25/41) and the discontinuity is declared.
- `platform`: `errors.csv` gains `code` and `event` columns (INV-PLT-19); write failures are counted, not swallowed.
- `campaign-analysis`: `violations.read_errors_csv` and `parse_payload` read the envelope and the new columns; `ERRORS_CSV_HEADER` changes in step with `platform`; `INV-CAN-04` counters extended to the new drop points it can see.
