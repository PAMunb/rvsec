## Subagent brief

**This group measures; it does not filter.** The three-clause arity rule is implemented and evaluated in the wrapper grouping loop, and the advice/overload pairs it *would* exclude are counted into `advicesExcludedByArity`, which travels to `instrument_results.json` and into `weave_counts`. **No advice is removed from any wrapper.** Emission after this group is byte-for-byte what it is before it.

Why counter mode: filtering changes what a merged wrapper fires, which changes which reports a device run produces, which changes the denominator of every other measurement in this change. The rule's own reach is partial by construction (four-class partition below), so a filter would silently move some reports and leave others, with no instrument in this change able to tell the two apart. Counting is the honest first step: it says how large the problem is, on a real descriptor, without moving anything. The filter is a follow-up decision that this group's evidence file is written to inform.

Read `design.md` D-6, the `instrumentation` delta (`Requirement: Arity Mismatch Is Measured, Not Filtered, in Wrapper Grouping`, INV-INS-122) and `openspec/changes/gh100-weaver-emission-fidelity/design.md` D-B1 (why wrappers merge). ## The rule being evaluated (verbatim source: `docs/20260815_javamop_mensagens_FINAL_analise_lacunas.md:674-684`)

1. Absence of an `args()` clause means "no positional constraint" — never count, never treat as length 0.
2. Read the length of `ArgsPC.types()`, not `names()`; a trailing `..` means "at least".
3. Evaluate in the grouping loop of `WrapperEmitter` — the only place advice and concrete overload coexist and `cc.paramFqns.size()` is known.

## The reach of the rule (task 4.5) — write this into `evidence/e2_reach.md` verbatim

A counter named `advicesExcludedByArity` invites the reader to assume it covers every arity-incompatible advice. It does not, on two grounds. First, `ArgsPC` is referenced only inside `pointcut-engine` (`ArgsPC`, `PointcutExpression`, `NegationPC`, `PointcutMatcher`, `PointcutExpressionParser`) — the entire `advice-emitter` package, `BeforeEmitter`/`AfterEmitter`/`AfterReturningEmitter`/`AfterThrowingEmitter` included, never reads it. Second, `PointcutMatcher.matchArgs` returns `Match.empty(ap)` unconditionally when `!ap.hasTypeConstraint()`, and the binding form (`args(alg)`, `args(alg, *)`) is exactly that case, so nothing constrains those advices at match time either. The grouping loop where the counter lives admits only `shouldWrap(a)` = `"after".equals(a.getPosition())` (`WrapperEmitter.java:161-163`) and drops constructors with an explicit `continue` (`:251-256`).

The frozen descriptor's 115 advices (`results/gh101_group8_jca_frozen_control/monitors/MultiSpec_1MonitorAspect.json`, 2026-08-08, byte-identical to `results/gh92_e2e2/monitors/`) partition as:

| any position, no `args()` | **44** | no — clause 1: no positional constraint |
