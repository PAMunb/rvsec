## The withdrawal (8.8)

Both resolve the same object-indexed monitor (the object is the value `getInstance` just returned, so the monitor is fresh), and `g1`'s body writes `currentAlgorithmInstance = alg` before the sibling's `condition` is evaluated. The field is initialised to `""`, never `null` (`M:4749`, `:6362`). The sibling fires exactly when `!contains(alg)` — which is what the repair would have produced. (On a fresh monitor the equivalence even survives the reverse order — `g4* g1` is accepted by the `ere`, `g4[0] = 0` — so the fragility is weaker than first stated; it is still declaration-order-dependent for a reused object.)
