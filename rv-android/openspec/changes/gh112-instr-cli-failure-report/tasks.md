## 2. Fix (GREEN)

- [ ] 2.1 `cli/src/main/java/br/unb/cic/rv/cli/BatchRunner.java`: add package-private `static String causeChain(Throwable ex)` that walks `getCause()` and joins each message with `"; caused by: "`. Bound the walk at 10 links — a self-referential or cyclic cause chain would otherwise loop forever, and the result is written into a JSON field, so a bounded string is wanted regardless.
- [ ] 2.2 Same file, lines 395-396: change `failed` to `failed(Path apk, String message, String phase, Map<String, Integer> counts)`, **drop the `private` modifier so the test in the same package can call it**, and store `counts` in the result; update the two early returns (`:157` config_validation, `:171` apk_read) and the two `catch` blocks (`:389-392`) to pass the live `counts`, use `causeChain(ex)` in the message, and call `ex.printStackTrace()` before returning.
- [ ] 2.3 Same file, lines 232-243 and 274-341: delete the twelve local `int` accumulators and accumulate into `counts` inside the weave loop — `counts.merge("matchesApplied", wr.matchesApplied(), Integer::sum)` and one call per counter, `counts.put("wrappersAliasedToSubtype", wr.wrappersAliasedToSubtype())` for the APK-scoped one, the coverage pair still under `if (coverageWeaver != null)`. `counts.put("wovenDexes", appDexEntries.size())` stays after the loop. Without this, 2.4's `dex_write` result still reports only the five pre-loop keys and the statistics of every DEX woven before the failure are lost — the half of the bug that passing `counts` alone does not fix. Check afterwards that every key still appears on a successful run (merge writes the key on the first iteration even when the value is 0, which is what the `plansSkippedUnresolvedBinding` jq guard in `run_phase5_validators.sh` relies on); the insertion order of `weaveCounts` in the JSON changes, which no consumer reads.
- [ ] 2.4 Same file, line 319: wrap `DexPool.writeTo(...)` in `try/catch (RuntimeException ex)` that prints the trace and returns `failed(apk, "DEX write failed for " + ed.entryName + ": " + causeChain(ex), "dex_write", counts)`.
- [ ] 2.5 Same file, lines 93-99 and 115-131: `instrumentOne` returns `result.success()`; `instrumentBatch` returns `results.stream().allMatch(PerApkResult::success)`; JSON write and stdout summary stay before the return.
- [ ] 2.6 `cli/src/main/java/br/unb/cic/rv/cli/InstrumentationCli.java`, lines 124-146: `Instrument` and `Batch` implement `Callable<Integer>`; `call()` returns `0` when the `BatchRunner` call returns `true`, `1` otherwise. `main` unchanged. Do not follow `ValidationCli`'s `System.exit`-inside-`Runnable` idiom: it would make 1.1 impossible to write in-process.
