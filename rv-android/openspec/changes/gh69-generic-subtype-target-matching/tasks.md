## Dependency map — what may run in parallel

The earlier list read `1 → 2 → 3 → 4 → 4b → 5`, which is a reading order, not a dependency graph. Only
**two** of phase 2's tasks actually need the extractor. The real shape is:

```
F0 (infra, serial, tiny)
   ├── Faixa A  (extractor)                 1.1 → 1.2/1.3 → 1.4/1.5 → 1.6 → 1.7 (install)
   └── Faixa B  (gator, extractor-free)     2.1, 2.3 → 2.4 ; 3.2b → 3.2c
                                            ↓ (both lanes complete)
                                        J (junção)  2.2, 2.4b, 2.5, 3.1, 3.2, 3.3
                                            ↓
                                        4 (rebuild + IT on the real scene)
                                            ↓
                                        4b (constructors — deliberately serial, see below)
                                            ↓
                                        5 (verification & review)
```

**Why the lanes are genuinely independent.** Faixa B's `TargetMethod` fields (2.1), the `TargetMatching`
helper (2.3) and its test (2.4) touch only `rvsec-gator` commons/client and Soot — they compile against
no extractor symbol. The `ReachabilityEngine` BFS-seeding repair (3.2b) and its tests (3.2c) are a
**pre-existing** defect fix (INV-ANA-64/D8), orthogonal to subtype matching. What genuinely needs the
fresh extractor JAR is only **2.2** (propagating `MopMethod`'s flags) and **2.4b** (loading a real
`generic_new` spec) — hence the junction, gated on **1.7** having installed it (D6/RISK-003).

**Two ordering constraints that are NOT negotiable.**
1. **1.7 before anything in J.** Phase-J code compiles against the new `MopMethod` API; building it
   against a stale `~/.m2` extractor is RISK-003, and the failure mode is a silent old-JAR link.
2. **4b stays serial, after phase 4 is green.** It is the one part of this change that deliberately
   moves frozen `jca` values, and its separability is the whole review story — see the phase-4b note.

**File-level conflict to respect if the lanes are worked by different hands**: `ReachabilityEngine.java`
is edited by **3.2b** (faixa B) and again by **3.2** (junção). They are sequential across the join, so
there is no concurrent write — do not hoist 3.2 into faixa B to "save a round trip".
