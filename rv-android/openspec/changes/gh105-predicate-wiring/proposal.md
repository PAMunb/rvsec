# Proposal: gh105-predicate-wiring

**GitHub Issue**: #105
**Track**: Full SDD
**Predecessor**: gh104 (`design.md` D-11), which named this change and built its prerequisite — the differential trace harness.
**Reference material (Phase 0, audited twice)**: `docs/20260820_plano_fiacao_predicados.md` (marks `[auditado]`/`[auditado-v2]`), `docs/20260820_auditoria_plano_predicados.md`, `docs/20260820_verificacao_plano_predicados_v2.md`, evidence in `audit/20260820_verificacao_plano_predicados_v2/`. ## Why

The `jca_android` specification set does not wire the CrySL predicates (`ENSURES`/`REQUIRES`/`NEGATES`): against the 33 api30 rules there are 19 connectable predicates (35 connectable `REQUIRES` clauses, 25 of them wireable in-set), and the set realizes 3 predicate links — so the whole class of parameter-spec misuse (static IV, reused GCM) is a false negative by construction, while all 27 predicate reads sit inside `condition(...)` where a false guard suppresses the transition and converts "unmodeled key origin" into a wrong `InvalidSequenceOfMethodCalls`, and 17 orphan accuser events sustain at most 39,682 events = 56.1 % of that published category — a ceiling measured over the `jca` campaign, not a causal attribution; the previously quoted 49,817 = 70.4 % is the frozen `jca`'s **ten**-spec orphan family, which includes `MessageDigestSpec` (10,135 events) whose orphan exists only there. gh104 made the `@fail` handler speak (envelope, codes, event names); this change makes it stop firing when it should not, and makes a violated `REQUIRES` accuse itself — on a substrate that indexes by identity like the monitors do, supports arity ≥ 2 (31 of 90 clauses need it), and distinguishes *violated* from *not observed*.

## What Changes

- **New predicate store classes in `rvsec-core`** (Java), used only by the `jca_android` specs: hybrid key (identity for the object binding, case-insensitive value with splitters for positions of type `String`/`int`/`Integer`), arity N, **three-valued** `validate` (satisfied / violated / not-observed), weak keys with purge, thread-safe. The API separates the bound object from the value positions — `ensure/validate(Property p, Object bound, Object... values)` — because a plain varargs head silently spreads a reference-array argument such as `KeyManager[]` into separate arguments (measured). `ExecutionContext` stays **byte-identical** — zero edits, not even an annotation: WORKFLOW.md P3 bans deprecation annotations, the annotation was measured inert in every build path, and byte-identity without exception is the stronger freeze claim (§3.1-bis revision, ratified by the researcher 2026-08-20). The freeze is protected by construction, not by vigilance.
- **`jca_android` automata absorb the 17 orphan accusers** (9 specs) — 8 of the 17 are negated twins of a conforming sibling (identical `call`/`args` pointcut, condition differing only in polarity) and are **fused** into the sibling's body rather than added as second events, which would make one call take two transitions; the rest are absorbed. This rescues the structural bucket of the failed attempt under fresh evidence, each change measured by the differential harness (F1).
- **The 27 predicate reads move from `condition(...)` to event bodies**, each clause-translating read with its accuser and a `codes.csv` code — including a new code for *not observed* that reaches the gh104 envelope (F2). The 8 guarded clauses (`alg in {…} => pred[…]`) evaluate their guard in the body before the read; the oracle's 3 negated clauses (`Cipher !macced`, `Mac !encrypted`×2) invert the three-valued table — absence satisfies — and are wired via `validateAbsent` (INV-INS-146, researcher decision 2026-08-20). Reads that translate no clause (propagation) gain no accuser.
- **Of the 35 connectable `REQUIRES` clauses, the 25 with both ends monitored in the set are wired in topological order** of the predicate graph (root `randomized` → `generatedKey`/`prepared*` → consumers), producer + consumer + accuser + satisfy/violate trace pair per task; the other 10 (consumer or producer rule without a specification in the set) are recorded, and `preparedEC` stays the one `unclosable` — the full 36-clause ledger lives in `design.md` (F3). Mechanism: hybrid per the executed IV-chain pilot — parametric junction specs (mechanism B) for co-observable chains including the `byte[]` family via the `Object` idiom, the new store (mechanism A) for value positions and edges without a co-observable chain.
- **Pointwise spec defects** fixed: `KeyPairSpec` private-key-as-public write, `TrustManagerFactorySpec` wrong property/pointcut, `SignatureSpec` verified-on-boolean, `SecureRandomSpec` autoboxed-argument marking and `end`-state `next2` omission, `SecretKeySpec` conflation (F4).
- **Of the 9 `remove()` sites, the 8 in `@fail`** — a semantics ("undo the predicate when the automaton fails") that exists in no CrySL generation — are removed with harness-measured deltas; only `PBEKeySpecSpec.mop:74` translates a real `NEGATES` clause and is kept on the new store (F4, plan D3).
- **New gate layer artifacts and gates** (F5): `predicate_graph.csv` (sibling of `constraint_table.csv`), G-ORDER (DFA equivalence against the rule's `ORDER`, with a versioned event-alphabet mapping), G-PRED2 (every `ENSURES`/`REQUIRES` clause has exactly its sites), G-ACC (every accuser has a loop in the automaton), G-PARAM (the `.mop` parameter list survives intact in the `.rvm` — the toolchain deletes it silently for primitive arrays, rc=0), and an import-discipline gate (`grep -rlw ExecutionContext` empty over `jca_android`). All gates satisfy the genericity contract: they run over all 214 `.mop` of the 5 sets, skip declaredly what does not apply, and count what they skipped (7 measured genericity gaps, plan §8-bis).
- **G-PRED is reformulated**: it stays as the byte-identity lock of the frozen `jca`; for `jca_android` it is retired and replaced by G-PRED2 + `predicate_graph.csv`. Collateral updated in the same task: `gh104_gates.py` (`accept_requires`, `PREDICATE_CALL`), `gh104_message_gate.py` (`_clause_family` classifies through `condition(...)` text, which F2 empties), `experimento-gh104/scripts/preflight.py` (a **second** gate also named G-PRED, carrying the withdrawn opposite polarity — retired/renamed), the `err2`/`c3` rows of `data/jca_android/gate_allowlist.csv` (their justifications cite condition reads F1/F2 change), and the INV-INS-128 pytest. **BREAKING** for the gh104 gate contract on `jca_android` (the `jca` lock is untouched); gh104's requirement "The Successor Set Carries the Predicates of Its Seed Unchanged" and INV-INS-123's premise ("encodes no `REQUIRES` by construction") are explicitly superseded for the migrated set.
- `rvsec-mop-defsuses` is retired to `backup/` and removed from `rvsec/rvsec/pom.xml` `<modules>` (the mid-level aggregator; the root pom does not list it) — its idea (def/use closure) is promoted to the `predicate_graph.csv` gate, which carries everything the module discards (site kind, polarity, arity, automaton membership).

## Capabilities

### New Capabilities

(none — this change modifies the existing runtime-verification pipeline contract; no new spec domain is introduced)

### Modified Capabilities

- `instrumentation`: the monitor-generation contract changes — predicate substrate (new store classes, `ExecutionContext` deprecated and frozen), predicate placement rules (reads in event bodies, never in `condition(...)`; writes at the rule's `ORDER` acceptance point), automaton completeness (no orphan accusers), junction-spec design rules (consumer never `creation`, benign loops for disconnected joins, `Object` idiom for primitive arrays), the three-valued verdict reaching the gh104 envelope with its own code, the new gates (G-ORDER, G-PRED2, G-ACC, G-PARAM, import discipline) and their genericity contract, and the reformulated scope of G-PRED. INV-INS-111 is realized for the successor set by INV-INS-137; INV-INS-128 is superseded for `jca_android` by INV-INS-141 (in force verbatim for `jca`); gh104's INV-INS-123 premise and its successor-set predicate requirement are superseded for the migrated set (restated inside the delta); new invariants INV-INS-130–147 are added.

## Impact

- **Java (rvsec reactor, sibling tree)**: `rvsec/rvsec-core` (new store classes; `ExecutionContext` untouched — byte-identical; `Property` gains constants append-only, never removed/renamed/reordered — measured safe: zero `ordinal()`/`values()` uses), `rvsec/rvsec-mop/src/main/resources/jca_android/` (23 `.mop` + `codes.csv`), `rvsec/rvsec-mop` test scope (`TraceRunner` trace pairs), `rvsec/rvsec/pom.xml` (`rvsec-mop-defsuses` removal from `<modules>`). The reactor build command and JDK constraints are unchanged.
- **rv-android modules**: none of the 16 Python modules changes behavior. The gate layer lives in `scripts/` (`gh104_gates.py` reformulation, new gate scripts) and `tests/parity/` (new and rewritten pytest gates), plus `data/jca_android/` records (`predicate_graph.csv`, alphabet-mapping artifact, `divergence_record.csv` rows for every spec hunk).
- **Frozen/archived sets**: `jca` (INV-INS-109/118: byte-identical, G-PRED green), `jca_android_bug_predicate` (archived; hunks may be reimplemented under fresh evidence, never copied), `generic`/`generic_new` (unchanged; they call no predicate substrate — 0 of 145 files reference `ExecutionContext` — and serve as the genericity test bed).
- **Oracles (read-only)**: `MetaCrySL/generated/api30/*.cryptsl`; rule defects become `divergence_record.csv` rows, never upstream edits.
- **Out of scope**: the weaver/instrumentation path (if `UnsatisfiedConstraint` stays at zero on the production path, this change is blocked and the weaver becomes a prerequisite — plan §9); gh104 Group 10 (final validation happens in the joint experiment `experimento-gh104/`); the article — it is not touched (researcher decision 2026-08-20: the corrected numbers, venn 300/322–255/355 and the 39,682 = 56.1 % orphan ceiling, serve the next experiments, not a revision of the published text); the upstream javamop/rv-monitor double patch for the primitive-array parameter collapse (root cause located at `javamop.jj:1456` + mirror, recorded as documentation only — the `Object` idiom bypasses it and G-PARAM guards the gap; no patch now or later in this line of work).
- **FRs/NFRs**: FR01-FR03 (monitor generation pipeline), NFR06 (measurement integrity), NFR07 (reproducibility — heap registered for every `Cipher` generation).
- **Risks carried from the plan**: R1 (freeze; mitigated by construction + import gate), R2 (generator ceiling — 17 events generate under 1 GB; n=18 is a hard parser limit; `CipherSpec` already stands at 17/17, so its headroom is **zero** and every new `Cipher` binding routes through junction specifications or the store, never new events), R3 (instrumentation reach — the *not observed* verdict is the mitigation), R4 (device `equals` of concrete keys — open, needs device), R5/R6 (silent toolchain failures — G-PARAM and artifact inspection, never exit codes), R7 (G-ORDER alphabet mapping as a budgeted task).
