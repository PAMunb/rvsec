- [x] 2.1 Declare two method-local caches `Map<Stmt,Integer> readFieldCache`, `Map<Stmt,Integer> writeFieldCache` before the outer `for (Expr e : allNAllocNodes.keySet())` loop (decision D4).
- [x] 2.2 Add private helpers `cachedReadContainerField(Stmt)` / `cachedWriteContainerField(Stmt)` using the `containsKey`-null pattern (NOT `computeIfAbsent`, which would not cache null returns) (D4, INV-ANA-39 purity).
- [x] 2.3 Hoist the read resolution with a **guard against node-creation side effects** (D3, point 2): build `List<NNode> readTargets` of the non-null target nodes `tn` once per alloc node (resolve `tgtPos` via `cachedReadContainerField`, compute `tn` exactly as the current inner block does, skip `tgtPos==null` / `tn==null` identically), but materialize it **lazily** — only on the first write that resolves to a non-null `sn`. Do NOT build `readTargets` (and therefore do NOT call `simpleNode`/`varNode` for the reads) for an alloc node whose writes all fail to resolve, because those factories (`FlowgraphRebuilder.java:794-839`) lazily create+register flow-graph nodes; the original never reaches the read loop in that case, so an unguarded precompute would create nodes the unoptimized pass does not (INV-ANA-39c). Hoists `R` not `W×R` resolutions.
- [x] 2.4 Rewrite the inner loop body to `for (NNode tn : readTargets) sn.addEdgeTo(tn);` — same edge set, no per-pair re-resolution; the surrounding write loop still does `resolve sn (cached) → skip if null → (lazy-build readTargets) → add edges` so the `if (sn==null) continue;` guard still gates whether any read-target work happens (D3).
- [x] 2.5 Replace the `wtgUtil.getWriteContainerField(src)` call at line 334 with `cachedWriteContainerField(src)` (D4 memoization across alloc nodes).
- [x] 2.6 Confirm the per-alloc `graphUtil.reachableNodes()` call (line 319) is left untouched (Non-Goal / Fix 2 deferred).
- [x] 2.6a Guard checkpoint (RISK-004) — **self-verified at implementation; §5.1 reviewer to independently re-confirm.** `collectReadTargets` (the sole read-side caller of the `simpleNode`/`varNode` factories) is invoked only at `FlowgraphRebuilder.java:366-367`, inside `for (Stmt src : writes)` and **after** the `if (sn == null) continue;` at line 363 — so for an alloc node whose writes all fail to resolve, `readTargets` stays `null`, `collectReadTargets` is never called, and no read-target node is created (identical to the original's nested read loop). The `readTargets == null` latch also bounds it to one call per alloc node (node creation is idempotent get-or-create, so the node set matches the original's per-write re-calls). INV-ANA-39c holds by construction.
- [x] 2.7 **Purity guard test.** Realized as `sootandroid/src/test/.../wtg/flowgraph/FlowgraphRebuilderCacheTest.java` (2 tests, green under `mvn -pl sootandroid test`). **Realization note:** the proposed `cachedReadContainerField(s) == wtgUtil.getReadContainerField(s)` *in-process* assertion is not supported by the existing test architecture — the rvsec-gator tests run the analysis as a **subprocess** (`GatorTestHelper` shells out to `./gator`), so there is no in-process `FlowgraphRebuilder`/`WTGUtil` to call the private resolvers on, and building an in-process Soot Scene fixture would be a major new harness (rejected, P1). Instead: (a) the **behavioral** purity proof — cached resolution yields an identical edge set — is delivered by the edge-set IT (4.A2) + corpus diff-zero (4.1), which exercise the real cached resolvers end-to-end via the JAR; (b) the **mechanical** D4 guard is locked by this static test, which scans the actual `FlowgraphRebuilder.java` (line comments stripped) asserting `0` `Map.computeIfAbsent` calls and that the cached resolvers gate on `cache.containsKey` (the null-caching pattern). Note: `computeIfAbsent` is a perf regression (re-resolves cached nulls), not an edge-correctness bug — INV-ANA-39 holds either way — so this guards the change's *purpose*, while 4.1/4.A2 guard correctness.

Neither was caused by gh66 (both reproduce on the pre-change JAR); both were fixed so the edge-set IT lives in a passing suite, as directed. Verified thoroughly before touching anything:

Fix = refreshed the two stale counts in `cryptoapp_baseline.json`; no code touched.

It is the upstream GATOR (Ohio State 2018) demo test that drives `Main.main` against hardcoded paths from the original author's machine (`~/workspace/android/Simplest`, `~/Android/Sdk`, `../tools/apktool_2.3.4.jar`) that do not exist here; `Main.main` calls `System.exit`, crashing the surefire fork.
