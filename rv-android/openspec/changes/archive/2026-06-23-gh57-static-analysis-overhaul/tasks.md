## 8. Codex pre-sweep correctness fixes (independent review 2026-05-15)

Four code-correctness defects flagged by an external review of `RvsecAnalysisClient.java`, `MenuExtractor.java`, and `SpinnerItemExtractor.java`. All four are small, ortogonal to the in-flight `cgDelegation` paridade gate (Group 6), and have measurable downstream impact on `reachable[]` / `widgets[]` quality. Land BEFORE the 380-APK sweep (Group 9) so the sweep validates the corrected pipeline. The corresponding spec deltas are recorded as sub-requirements under the existing "Unified Static Analysis" and "Programmatic …" requirement blocks (see `specs/analysis/spec.md`).

- [x] 8.1 **Codex #1 — isolated entry-point seeds.** `RvsecAnalysisClient.multiSourceBfs` (line ~411) gates `visited.add(seed)` on `graph.containsVertex(seed)`, but `buildJGraph` (line ~387) only adds vertices that appear in some CG edge. Entry points without any outgoing/incoming SPARK edge therefore disappear from `reachable[]` even though they are legitimate seeds — inflating the "dead code" reading of coverage denominators. **DONE** — `multiSourceBfs` now does `graph.addVertex(seed)` before `visited.add(seed)`; an INV-ANA-25 comment explains the invariant.
  - [x] 8.1.1 Unit tests for #1 in `ReachabilityBfsTest`: `testIsolatedSeedSurvivesEmptyGraph`, `testIsolatedSeedAlongsideConnectedSeed`, `testAllSeedsIsolatedAreAllReturned`; plus rewrite of pre-existing `testBfsSeedNotInGraph` which now asserts the seed survives (was `assertTrue(result.isEmpty())`, now `assertEquals(setOf("X"), result)`).
- [x] 8.2 **Codex #5 — `@+id/` filter.** `enrichFromElement` (line ~1031) accepts only `id.startsWith("@id/")`, but the dominant declaration form in Android layouts is `@+id/foo`. Most XML-declared widgets are silently skipped by the enrichment pass, which is the likely reason G3 attribute coverage looked low on partial smokes. **DONE** — `enrichFromElement` now detects either prefix dynamically (`idPrefix` derived from `@+id/` or `@id/`) before the substring lookup.

- [x] 8.3 **Codex #6 — MenuExtractor resource-id resolver.** `RvsecAnalysisClient` constructed the extractor with `new MenuExtractor(resId -> null)` (line ~798). Any `Menu.add(group, id, order, R.string.foo)` produced an item with `text=""`. **DONE** — closure now calls a new private helper `resolveStringIdToName(resId, appPkg)` (lazy-built `Map<Integer,String>` from `<appPkg>.R$string` static fields via `IntegerConstantValueTag`), then chains to existing `resolveStringReference(resDir, name)`.
