- [x] 5.2 **`compare` and `lower` are wired; `calibrate` is not, and says so.** `cli/ConformanceCli.java` keeps `main`, `run(args, out, err)` returning an `ExitCode` without ever calling `System.exit`, the JCommander dispatch and the three argument objects. Two of the three bodies now do the work.
  - `runCompare` → `cli/CompareRun`: builds both `Version` stamps, lifts the `.mop` side with `MopLifter.read` (each `LiftFailure` counted, never fatal), indexes `--android-jar` with `ApiIndex` and reads its access flags with `Observability`, loads `--alphabet` with `AlphabetMap.read`, lifts the oracle with `CryslLifter.liftCorpus`, pairs by declared type with `SpecRulePairing`, builds the corpus-wide `PredicateGraph`, and runs **M0 first for every specification** — paired or not — handing M1–M4 to `Pipeline.run` as a **supplier**. That is INV-CONF-09 as a mechanism rather than a filter: for a refused specification the supplier is never invoked, so the four verdicts are not produced, and the CSV/Markdown rows are collected *from inside the supplier* for the same reason. Emission is JSON (`conformance_report.json`), CSV in the committed schemas (`predicate_graph.csv`, `constraint_table.csv`, and `divergence_record.csv` from M0's `divergences()`, which is where D-04 says those silences belong) and Markdown (`m1_events.md`, `m2_order.md`, `m4_predicates.md`) — all through `core.emit`, all under `--out` and nowhere else (INV-CONF-12).
  - `runLower` → `cli/LowerRun`: lifts each file, `MopLowerer.lowerTo` into `--out`, then `RoundTripGate.run`. Layer 1 is what decides (`passed()`); the round trip is printed **beside** it (`faithful()`) and not folded into it, because "the emitter lost a field" and "the emitter wrote something unsound" are different findings. Layer 2 does not run — it needs the paired rule's language and `LowerArgs` declares no `--rules-dir` — and the run says so on its own line rather than leaving a reader to assume it passed. The verdicts go to the stream and not to a table on purpose: every `core.emit` table carries **two** stamps and `lower` has no oracle, so a stamped table of its verdicts could only be built by inventing an oracle stamp — the exact failure INV-CONF-01 exists to prevent.
  - **`calibrate` still refuses with `ExitCode.NOT_WIRED`, and that is the correct state, not an omission.** `CalibrationGate`, `CalibrationTargets` and `CalibrationMismatch` are G12's and do not exist. A gate that always passes is worse than no gate, and stubbing one here would manufacture exactly the artefact this change exists to remove. `ExitCode.NOT_WIRED`'s Javadoc now names `calibrate` as its only remaining producer, and the package-info says the same.
  - One decision worth recording because it is visible in the output: every metric names a specification by the file name **without** `.mop`, which is what `M0Vitality` derives and what `constraint_table.csv` already holds. The committed `predicate_graph.csv` writes `CipherSpec.mop` in its `file` column and the emitted one writes `CipherSpec`, so one specification has one identity across the five metrics of a single report. The schema — the columns — is untouched, and `CommittedSchemaDriftTest` still passes.
  - A second one, stated in the counting rule rather than in a comment: **N3 is not applied.** Which states a specification marks accepting purely to give a predicate an acceptance point is human judgement (the `alias match*` names do not survive the lift) and `compare` has no argument to declare them, so the M2 verdicts are taken over the full accepting set. `CompareRun.N3_NOT_DECLARED` is appended to the M2 counting rule and `CompareSmokeIT` asserts it reaches the report, because it changes what the verdict means (INV-CONF-02).

## Closing
G05 closes when 5.1–5.11 are `[x]`.

**Closed (2026-08-24).** All 11 are `[x]`. The four that were open — 5.2, 5.3, 5.5, 5.8 — were
open because the code they call did not exist; it does now, and they were closed by wiring it, not
by lowering the bar. `compare` runs M0–M4 through `Pipeline` and emits three formats; `lower` runs
`MopLowerer` plus `RoundTripGate`; both refuse an empty corpus rather than measuring it.

**What is deliberately still refusing, and why that is the right state.** `calibrate` throws
`NotWiredException` and exits `70`. `CalibrationGate`, `CalibrationTargets` and
`CalibrationMismatch` belong to G12 and do not exist, and a gate that always passes is worse than
no gate: it is the artefact this whole change was created to remove, wearing the change's own
badge. For the same reason `ConformanceCli.run` still has no `CalibrationMismatch` catch arm — the
exit code is reserved, the site is marked, and G12 adds the arm when it creates the type.

**Two limits of the wired `compare`, recorded because they are visible in what it emits.** N3 is
not applied, because the predicate-only accepting states are a per-specification judgement and
there is no argument to declare them; this is stated in the M2 counting rule that travels with
every verdict. And M4 runs under `Judgements.empty()`, so the derived fraction of its fidelity
classification is what the metric derived and nothing that was handed to it.

**Green, with the counts beside it.** `mvn -o -f rvsec/rvsec-crysl/pom.xml test`: `-core` **154**,
`-mop` **58**, `-crysl` **94**, no `Tests are skipped.` line. With
`-DexcludedGroups=oracle-dependent`, the shape CI runs: **154 / 57 / 36**. `mvn -pl rvsec/rvsec-crysl
-am test` remains the false-green form — it selects the aggregator, runs zero tests and prints
BUILD SUCCESS — and must not be used to check any of this.
