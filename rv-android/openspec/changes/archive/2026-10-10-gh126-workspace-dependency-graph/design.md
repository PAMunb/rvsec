It also records the author's decisions of 2026-10-10: one change, no behaviour change, the four `Task` helpers deleted, and the `task.py` comments corrected without touching the code. ## Goals / Non-Goals

**Goals:**
- The declared graph equals the imported graph. The one exception is `aperv-tool → rv-coverage`, which stays undeclared as a recorded decision.
- `rv-android-core` has no workspace edge, declared or imported.
- The installed set and every runtime path stay the same.
- Every document that states an edge this change removes or adds says the new thing, except the Views-and-Beyond documents in `docs/architecture/` (Non-Goals).

**Non-Goals:**
- `_new_repository()` code. It always returns `None` at runtime, and `ResultProcessorComponent` (`result_processor.py:589`, `:1021`) reconstructs from the logcat only when `task.repository` is falsy. A real empty `LogcatRepository` has no `__len__`/`__bool__`, so it is truthy, and returning one would make resume skip the reconstruction and report empty coverage.
- The `try/except` guards in `rv_platform/__init__.py`.
- `aperv-tool`'s lazy `rv_coverage` import (`analysis/step_bundle.py:193`).
- The SDP edge `rvagent-tool → rv-agent`.
- Layer rules in `.claude/skills/rv-analyze-dependencies/reference.md` beyond its allowed-edge table.
- The Views-and-Beyond documents in `docs/architecture/`. Another session holds an uncommitted regeneration of them, so editing them here would mix that session's work into this change's commit (author's decision, 2026-10-10). That work, or a later `/rv-doc-arch` run, corrects their edges.

## Decisions

**D1 — Delete the four helpers instead of moving them.** `get_repository` duplicates `_reconstruct_repository_from_logcat` and has already drifted from it: it omits `tool_execution_start` (INV-PLT-23). `add_error` and `add_method_call` call `_new_repository()`, which returns `None`, so on a fresh task they register nothing. `update_coverage` writes `task.result.coverage_metrics` and a `task.coverage_metrics` attribute that no `src/` code reads; coverage reaches `task.result` through `CoverageComponent` (`rv_platform/components/coverage.py`). *Alternative:* move `get_repository` into rv-platform. Rejected, because rv-platform already has the correct implementation, and a second copy would be a second place to keep INV-PLT-23. The files go to `backup/20261010-gh126-task-coverage-helpers/` first (P3).

**D2 — Remove the type aliases that lose their users.** After D1, `RvCoverageLog` and `RvErrorLog` (`task.py:34`, `:38-39`) are referenced nowhere in the file. They go, together with their `TYPE_CHECKING` import. `LogcatRepository` stays, because `_new_repository()` and the `__init__` annotation use it. `os` stays (`initialize()` uses it).

**D3 — Correct the comments to state the runtime fact and the reason it matters.** The two comments (`task.py:583-585`, `_new_repository` docstring `:602-603`) and the `__init__` docstring line (`:556-557`) say the fallback is active when rv-coverage is not installed. The class lives in `rv_android_core.domain.coverage` and is imported under `TYPE_CHECKING`, so at runtime the name is always `typing.Any` and `_new_repository()` always returns `None`. The new text says that, and that `ResultProcessorComponent` relies on a falsy `task.repository` to reconstruct from the logcat. Per P4 it says what the code does now and nothing about what it used to say. The same correction covers every other comment that makes the claim or that the deletion leaves stale (author's triage, task 7.5): the two `# Fallback for when full dependencies aren't available` lines above `App = Any` and `LogcatRepository = Any` go, because the block comment above them states the runtime fact; the import comment at `:16` (`TYPE_CHECKING import to avoid missing dependencies during tests`) is reworded; and the `_new_repository()` docstring loses its "Build a repository" summary and its "several of these construction sites" sentence, since one call site remains and it returns `None` at runtime.

**D4 — `rv-static-analysis` moves to `rv-agent`'s `dev` group instead of being removed.** Six test files import it: `tests/unit/test_gh77_mop_reach.py`, `test_rvagent_visitor.py`, `test_transition_manager.py`, `test_navigation_guidance.py`, `tests/online/test_static_analysis.py`, `tests/online/conftest.py`. The `dev` group records that coupling without making it a runtime edge. The group also needs the workspace source entry, which stays in `[tool.uv.sources]`.

**D5 — Narrative spec sections are corrected by hand at archive.** `openspec archive` merges requirement blocks and leaves Purpose and Invariants sections alone. The delta specs name exactly which narrative passages and invariants to edit: `tools` design decision 3, the `tools` "Dependencies" list, INV-TOOL-12 and the new INV-TOOL-26, and the `aperv` Purpose paragraph and `rv-tools` relationship entry. The archive task performs those edits and checks them by grep.

**D6 — Root `CLAUDE.md` coordination.** The root `CLAUDE.md` has an uncommitted edit by another session (the P4 exception for ADRs). This change edits a different block (the module map). The commit takes the file by path only after confirming with the author that the other edit may go in the same commit or has been committed first (memory: shared tree, commit by path).

**D7 — Parallel execution with the main session as a thin orchestrator (author's decision, 2026-10-10).** The main session edits no file. It dispatches subagents, reads their short reports, runs the barrier steps, checks the no-behaviour-change evidence itself, archives and commits. The evidence is read by the main session, not taken from a subagent's report, because it is what supports the claim that behaviour did not change. Work is split by file ownership, so no two concurrent agents write the same file:

| Owner | Files written | Starts after |
|---|---|---|
| R (baseline) | `experimento-gh126/run_evidence.sh`, `experimento-gh126/baseline/` | — |
| D1 (docs: guidance) | root `CLAUDE.md` (module map rows only), the 8 module `CLAUDE.md`, `.claude/skills/rv-analyze-dependencies/{reference.md,SKILL.md}`; at triage (7.5) also the `docs/architecture.md` of rv-uiautomator, rv-experiment, rv-coverage, rvagent-tool, aperv-tool, rv-platform and the `README.md` of rv-uiautomator, rvagent-tool, aperv-tool, rv-agent | — |
| D2 (docs: core architecture) | `modules/rv-android-core/docs/architecture.md` | — |
| A (core) | `task.py`, `test_task.py`, `backup/20261010-gh126-task-coverage-helpers/` | R |
| P (declarations) | the six `pyproject.toml`, `uv.lock` | R |
| main (barrier) | `.venv` via `uv sync`, `experimento-gh126/after/` | A, P |

The waves follow from three measured facts of 2026-10-10:
- **The baseline must precede every edit it measures.** That is why A and P wait for R.
- **No test reads the `.md` files this change edits.** The only tests that read a `CLAUDE.md` read the ones of `rv-static-analysis` (`tests/parity/test_gh111_specset_ruler.py`) and `rv-instrumentation-ajc` (`test_scope_key_policy.py`). D1 and D2 can therefore run during the baseline.
- **A and P share no file, but `uv sync` rewrites the shared `.venv` that A's test run imports from.** P therefore runs `uv lock` only, and the main session runs `uv sync` once both are done.

Running every wave in sequence would cost the sum of the agents' times. The parallel plan costs the longest path, R → max(A, P) → evidence → review, plus the doc agents, which overlap with all of it. *Alternative:* one agent per task group in sequence. Rejected, because the doc work, the longest edit, would sit on the critical path for no reason.

**D8 — Lint only the two files the change edits.** `/rv-qa-lint-fix rv-android-core` reformats the whole module. Other sessions have uncommitted edits in the working tree, and a module-wide fix would rewrite them and mix them into this change. The lint step is therefore run on `domain/task.py` and `tests/domain/test_task.py` only (`ruff check --fix` and `ruff format` on the two paths). `/rv-verify rv-android-core` still runs over the whole module, because it only reads.

## API Design

No public API in `src/` changes, apart from the removal of four `Task` methods that no production caller uses:

| Removed | Former contract | Replacement in production |
|---|---|---|
| `Task.get_repository() -> LogcatRepository` | Return `self.repository`, re-parsing `result.logcat_file` with `rv_coverage` when it is `None` | `ResultProcessorComponent._reconstruct_repository_from_logcat(task)` |
| `Task.add_error(error)` | Register on `self.repository` if not `None` | `CoverageTracker` registers on the repository it owns |
| `Task.add_method_call(coverage_log)` | Same, for coverage logs | Same |
| `Task.update_coverage()` | Copy repository metrics into `result.coverage_metrics` | `CoverageComponent` writes `task.result.coverage_metrics` |

## Data Flow

Unchanged. Live coverage flows `LogcatManager` → `CoverageTracker` (rv-coverage) → `LogcatRepository` owned by `CoverageComponent` → `task.repository`. On resume it flows `ResultProcessorComponent._reconstruct_repository_from_logcat` → `parse_logcat_file` (rv-coverage) → `task.repository`. Neither path passes through the removed methods.

## Error Handling

| Error | Source | Strategy | Recovery |
|-------|--------|----------|----------|
| `ImportError` for `aperv_tool` | `rv_platform/__init__.py` | Unchanged: logged as warning, platform imports | Fix the failing import |
| `uv lock` resolution failure | lock regeneration | Stop; the edges removed narrow the graph and cannot create a conflict, so a failure points at an unrelated drift | Inspect with `uv lock --dry-run` |
| `AttributeError` on a removed method | any caller outside `modules/*/src` | Pre-checked by grep over the whole repository, `scripts/` and `experimento-*/` included | Not expected |

## Risks / Trade-offs

- [A caller outside `modules/` uses a removed method] → Grep the whole rv-android tree for the four names, excluding `.venv/` and `backup/`, before deleting (task 1.1). On 2026-10-10 the only hits outside `src/`/`tests/` were in `backup/`.
- [The install set changes unnoticed] → Export the resolved set before and after with `uv export --frozen --no-hashes` (with and without `--no-dev`) and diff it with comment lines removed. That diff MUST be empty (task 6.4). The raw diff is not empty: `uv export` annotates each package with `# via <member>` comments derived from the member edges, so those comments change with the edges this change edits, while the package and version lines stay identical.
- [A test in another module relied on the removed helpers] → Grep over `modules/*/tests`; on 2026-10-10 only `rv-android-core/tests/domain/test_task.py` used them.
- [Documentation drift] → The doc inventory in the proposal comes from a grep. Tasks 2.4 and 3.2 re-run it after the edits.
- [`uv sync` touches a `.venv` that other sessions share] → It runs once, at the barrier, after `uv lock`. The resolved set is the same before and after (task 6.4), so the sync only refreshes metadata of the editable members.
- [A subagent changes git state in the shared tree] → Every prompt forbids `stash`, `checkout`, `switch`, `restore`, `reset`, `branch`, `rebase`, `clean` and `commit`, and allows only `diff`, `status`, `log`, `show` and `grep`. To compare before and after, a subagent uses `git show HEAD:<file>` into its scratch directory.
- [Concurrent agents write the same file] → Ownership is disjoint (D7). The root `CLAUDE.md` is owned by D1 alone, and D1 edits only the module-map rows.

## Testing Strategy

One test is written: `test_task.py` pins that a new `Task` starts with `repository` set to `None` (author's triage, task 7.5). The comments call that `None` required, the resume path depends on it, and the deleted classes held the only core test that touched it; otherwise it would be covered only indirectly, by rv-platform's two-session resume test (`tests/execution/test_resume_integration.py:546`). The change otherwise removes code and edges, and the evidence that behaviour is unchanged comes from the existing suites plus three checks:

| Layer | What to test | How | Count |
|-------|-------------|-----|-------|
| Install set | Resolved packages identical | `uv export` before/after, diff empty once `# via` comment lines are removed | 2 diffs |
| Graph | Declared = imported, no cycle | `workspace_deps.py` | 1 run |
| Smoke | Both plugins register on `import rv_platform` | one-line `uv run python -c` | 1 |
| Unit/integration | Suites of the modules whose files change | `uv run pytest modules/<m>/tests` for rv-android-core, rv-platform, aperv-tool, rvagent-tool, rv-agent, rv-uiautomator, rv-experiment | 7 modules |
| Cross-cutting | The root gates CI runs | `uv run pytest tests` | 1 |

Every pytest run uses CI's flags: `--import-mode=importlib -o "addopts=" -m "not (slow or online or sglang or performance or dataset)"`. It also passes `-p no:cacheprovider`, so concurrent runs do not share `.pytest_cache`. One script, `experimento-gh126/run_evidence.sh <label>`, runs everything in parallel and writes `experimento-gh126/<label>/`: the two `uv export` files, the `workspace_deps.py` output, one log per suite, and `summary.txt` with each suite's final pytest line and wall time. The script is evidence tooling and is not committed.

Measured on 2026-10-10 with the tree as it was before this change:

| Suite | Wall (parallel) | Result |
|---|---|---|
| rv-android-core | 7 s | 1150 passed, 4 deselected |
| rv-platform | 11 s | 366 passed, 1 skipped |
| aperv-tool | 61 s | 760 passed, 25 skipped, 1 deselected |
| rvagent-tool | 5 s | 37 passed |
| rv-agent | 50 s | 1950 passed, 16 skipped, 71 deselected |
| rv-uiautomator | 2 s | 114 passed |
| rv-experiment | 5 s | 294 passed |
| root `tests/` gates | 3 min 50 s | 299 passed, 2 skipped |

The seven module suites together take about 61 s. The root gates set the critical path, about 4 min per evidence run. The baseline the change compares against is the one task 1.3 records at the start, not these numbers, because other sessions keep editing the tree. The `rv-android-core` suite loses the tests of the three deleted classes (task 4.4) and gains the one pinning test, so its count is the baseline minus 11 plus 1. Every other count stays the same.
