# Risk Register — gh56-instr-binding-correctness

**Change**: gh56-instr-binding-correctness
**Date**: 2026-05-14
**GitHub Issue**: #56

This register tracks risks identified during the gh56 design phase plus residuals surfaced by the adversarial review (Claude / Codex / Gemini analyses, see `docs/analise_*.md`). Mitigation status reflects what has been implemented in the change; "residual" rows describe risks accepted at change-archive time.

## Residual Risks Accepted at Change Closure

- **R4 (cross-APK regression beyond cryptoapp)**: gh56 is an instrumentation-fix change, not an ecosystem-measurement experiment. Broader validation is downstream work with its own change, dataset, and timeline. The `plansSkippedUnresolvedBinding` counter is the canonical regression trip-wire for any future instrumentation run that touches a wider APK set.

## Out of Scope (declared in design.md "Non-Goals")

These items are **not** risks within gh56 — they belong to other changes:

- Overload enumeration in `expandCallTarget` (`Mac.update([B)V`, `SSLContext.init`, …) → `gh<N+1>-instr-pointcut-completeness`.
- Kotlin `suspend` / CPS state-machine detection (INV-INS-61 residual) → separate change.
- `Format35c` for registers `>v15` (INV-INS-32 residual) → orthogonal mechanic, separate change.
- `InheritanceResolver` Phase 2 expansion for custom Cipher subclasses (`wrappersAliasedToSubtype` residual) → separate change.
- A centralised `rv-validator` Python module or `.github/workflows/` CI pipeline for the oracle gate → infrastructure change, separate.
- Re-running any portion of the 2026-05-08 campaign (sampled or full) → cross-APK measurement is a separate experiment with its own change.
- The AJC variant. AJC has its own structural defects (gh54 R8/Compose residuals) and uses a completely different emission path → separate change.

## Review Sources

This register incorporates findings from three parallel adversarial LLM reviews of the gh56 SDD artefacts:

- `docs/analise_claude.md` (Claude Opus 4.7 1M) — 3 P0 blockers (mergeBindings, API propagation, layering), 1 P1 critical (circular type-matching). All addressed.
- `docs/analise_codex.md` (GPT-5 Codex) — 6 P0 blockers (validator exit code, runner invocation, script signature, type naming, WeaveReport surface, hardcoded path). All addressed.
- `docs/analise_gemini.md` (Gemini) — 0 blockers reported (the dissenting review; missed everything Claude and Codex caught). Treated as a calibration signal: when N-1 reviewers find blockers and 1 does not, trust the consensus.

The consistency audit (cross-artefact verification of invariant IDs, design references, file/line citations, test count, exit code semantics) is documented inline in the change commits.
