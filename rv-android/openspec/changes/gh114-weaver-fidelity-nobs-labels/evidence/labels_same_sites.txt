What is compared
----------------
The specification trace harness replays every trace of rv-android/data/gh104/traces through
two generated monitors and records, per trace, every report (envelope) and the event that raised
it. No weaver is involved: TraceRunner calls the generated static dispatchers directly.

  A = the jca_android set at HEAD (c819b721), extracted with
      git archive HEAD rvsec/rvsec-mop/src/main/resources/jca_android | tar -x -C <scratch>/A
  B = the jca_android set of the working tree (the .mop edits of G6, G7, G8, G9a, G9b and the
      merged codes.csv of task 13.1), copied to <scratch>/B/jca_android. It was copied rather
      than passed in place because monitor generation writes .rvm files into the specification
      directory, and G13b was editing comments in that directory during the run. The copy
      differs from the final working tree only in comment lines of DigestOutputStreamSpec.mop.

A site is (spec, event, class, method, location). In the replay, class, method and location are
the trace line itself: each report is raised by one dispatcher call made for one line of one
trace, and both sides replay the same lines (the unresolved lines are identical on both sides,
7 per side, all pre-existing: MessageDigestSpec-reset.txt `md.reset()` and six `String.valueOf`
/ `toCharArray` lines of the RandomStringPasswordSpec traces). So the per-trace comparison is
over the (spec, event) of every report, where spec is the envelope's `spec=` and event is the
dispatcher's event (the outer `ev=`), counted with multiplicity.
