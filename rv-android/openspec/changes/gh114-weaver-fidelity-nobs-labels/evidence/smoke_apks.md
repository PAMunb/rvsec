`SSLContext.init` through a TLS client, one with embedded BouncyCastle, one with a hooked
`Cipher.init` that is a branch target, and one with a `KeyStore.getEntry` call. The choice is made
from the before-sweep over the 163 APKs instrumented with `jca_android` + dexlib2

pass; they are not columns of the sweep, which names no library.

## WAVE 3 — the instrumentation the sweep and the smoke run on (task 15.2)

Source of the originals: `/home/pedro/desenvolvimento/RV_ANDROID_NOVO_DATASET/APKS`, copied
unchanged into a work directory of the session scratchpad (`smoke_orig/`).

Production path, one command, no static analysis (instrumentation does not read it; the smoke's
coverage cells are therefore empty, which is not what the smoke checks):

```
uv run rv-experiment run --tools ape --specification-set jca_android \
    --instrumentation-variant dexlib2 --apks-dir <scratch>/smoke_orig \
    --skip-static --skip-execution --output-dir <scratch>/gh114_smoke
```

The monitor of `jca_android` was generated by the same pipeline into `<scratch>/gh114_smoke/monitors`
(47 specifications; `MultiSpec_1MonitorAspect.json` is the descriptor the sweep reads), and the
instrumented APKs landed in `<scratch>/gh114_smoke/instrumented_apks`, which is the `--apks-dir` of
the smoke (task 15.4).

All four succeeded (`instrument_errors.json` empty), with the weaver of task group 17:
