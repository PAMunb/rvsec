# Proposal: gh62-aspectj-grammar-coverage

## Why

The dexlib2 instrumenter (`rvsec-android/rvsec-instrumentation-dexlib2/`) has accumulated five incremental fixes (`gh52`, `gh56`, `gh57`, `gh59`, `gh61`), each targeting a single observed gap surfaced by a downstream symptom (a `VerifyError`, a missing `g2` event, a wide-slot binding bug). A cross-LLM artifact review of `gh61` (Codex GPT-5, DeepSeek, Gemini 2.5 Pro, Claude Opus 4.7), a round-5 expansion by nominal AspectJ family, a round-6 redesign by corpus demand, a round-7 re-audit against the logging aspect `aspect/Coverage.aj`, and a round-8 absorption-aware re-scoping (six new cross-LLM analyses + three empirical audits on 2026-05-26) revealed that this reactive posture leaves **silent gaps** in production: pointcuts that parse without error, weave without crashing, and emit nothing — invisible without an external oracle.

Four classes of silent failure are confirmed against the current `HEAD` of `origin/modules`:

1. **Matcher always-match for unmodelled designators.** `PointcutMatcher.java:109-114` collapses `IfPC`, `NamedRefPC`, and `WithinPC` into `Match.empty(pe)` regardless of the underlying expression. Every pointcut that the parser cannot model becomes a `NamedRefPC` (`PointcutExpressionParser.java:131-132`), which means `this(...)`, `withincode(...)`, `cflow(...)`, `cflowbelow(...)`, `handler(...)`, `initialization(...)`, `preinitialization(...)`, `get(FieldPattern)`, `set(FieldPattern)`, and (modulo upstream absorption — see Round-8 absorption-aware demand below) the historically-suspected `adviceexecution()` are all silently always-match in this code path. The AspectJ 5 annotation family (`@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`) reaches the parser through a different failure mode: `PointcutExpressionParser.isIdentPart()` rejects `@` as an identifier character, so the parser raises `PointcutParseException` before reaching the `NamedRefPC` fallback. The end-state verdict is still SILENT-GAP for both code paths (the gap surfaces as a parse-time exception that callers catch and downgrade), but the matcher always-match description does not apply to the annotation family.
2. **Strict `.equals()` against unmodelled descriptors for partially-modelled forms.** `T+` in `call()` owner position (`PointcutMatcher.java:153-157`), `T+` in return type, `*` wildcard in method name (`PointcutMatcher.java:161-167`), and trailing-mixed `(T, ..)` varargs (`PointcutExpressionParser.java:271-273` — `isVarargs` only accepts `..` as the sole element) fail to match because the matcher does literal string equality without expanding subtype/wildcard/varargs semantics.
3. **Silent emitter no-op.** `DexWeaver.java:560-566` has `case TRY_CATCH_WRAP: case REPLACE: break;` — `after() throwing(...)` plans are generated by `AfterThrowingEmitter` and silently discarded by the weaver with no log, no counter, no exception. The standard test surface — green bar against the JCA fixtures — cannot detect any of this.
4. **Silent matcher/emitter gaps for MOP-specific constructs that reach the pipeline.** The dexlib2 instrumenter exists because AspectJ's offline weaver breaks on newer Android apps; for it to be a drop-in replacement, the constructs that the JavaMOP-compiled `.aj` and the `AspectDescriptor` JSON actually deliver to the instrumenter must have functional equivalents. Round-5 cross-LLM review and the round-8 empirical audit (`docs/analise_sintese_macro.md` §3.2) jointly identify the following high-demand constructs whose dexlib2 path is silently broken in the post-absorption pipeline: (a) positive `within(typePattern)` — 28 sites, matcher always-true; (b) `T+` in `call()` owner position — extensive use in `generic_new/`, gh61 only covered parameter position; (c) `!target(T)`/`!args(T)` — 32 sites in `generic_new/`, parser collapses to `NamedRefPC`; (d) method-name glob `name*` — ~16 sites in `generic_new/`; (e) `staticinitialization(T+)` synthesis when `<clinit>` is absent — 6 sites; (f) `after() throwing(...)` end-to-end weaver install — 2 sites; (g) `(T, ..)` trailing-mixed varargs — 14 jca + 2 generic_new; (h) `target(Type)`/`args(Type)` type-matching — 54 sites in generic_new; (i) `if(...)` AspectJ PCD semantic evaluation — 8 sites in generic_new; (j) `BaseAspect.notwithin()` named-ref expansion — 2 sites; (k) the `NamedRefPC` resolver against the (round-8-narrowed) per-aspect symbol table needed by `BaseAspect.notwithin()`.

### Round-8 absorption-aware demand

Round-7 framed scope by **source-level `.mop`/`.aj` demand** and proposed twenty in-change closures. The round-8 audit (`docs/analise_sintese_macro.md` §3, three empirical investigations) reframed scope by **pipeline-level demand**: the demand that actually reaches the dexlib2 instrumenter after the upstream stages (JavaMOP compiler, `coverage-weaver`, MonitorRuntime dispatch loop) have absorbed everything they can absorb. Seven of the twenty round-7 closures attacked source-level constructions that the upstream pipeline never delivers to the instrumenter:

- **`condition(...)` (§4.G, 74 sites source-level)** — JavaMOP compiler folds the condition logic into the `*RuntimeMonitor.*Event(...)` method body. Compiled `.aj` (`results/gh53_smoke_dexlib2/monitors/MultiSpec_1MonitorAspect.aj:212-218`) contains **zero** `condition(...)` references. Reclassified NOT-NEEDED β.
- **`__STATICSIG` JavaMOP macro (§4.S, 3 sites source-level)** — expanded by JavaMOP compiler before emitting `.aj`. Compiled JCA `.aj` contains **zero** `__STATICSIG` / `toLongString` references. `generic_new` audit pending as archive precondition. Reclassified NOT-NEEDED β.
- **`adviceexecution()` real semantics (§4.A, 2 sites source-level — both in `commonPointcut: !adviceexecution()`)** — vacuously true in the dexlib2 inline-call emission model. Dexlib2 emits `invoke-static *RuntimeMonitor.*Event(...)` at matched call sites; AJC-style advice methods (`ajc$before$...`) do not exist; the negation has nothing to exclude. Reclassified NOT-NEEDED β.
- **AspectJ runtime substrate `br.unb.cic.rv.aspectjlang.*` (§4.RT, ~600 LOC + ~150 LOC remap)** — sole consumer was Coverage.aj (1 aspect-site `org.aspectj.lang.*` imports). Coverage.aj is absorbed by `coverage-weaver` (see entry below). Reclassified NOT-NEEDED β.
- **`thisJoinPoint*` bindings end-to-end (§4.JP, ~250 LOC)** — APK inspection of `results/gh53_smoke_ajc/instrumented_apks/cryptoapp.apk` shows 115/115 MOP advices have **zero** `JoinPoint`/`Signature`/`thisJoinPoint` references in the woven smali. Only `Coverage.aj` consumed these — and `Coverage.aj` is absorbed. Reclassified NOT-NEEDED β.
- **`Coverage.aj` end-to-end (§4.CV)** — `coverage-weaver` module (`rvsec-android/rvsec-instrumentation-dexlib2/coverage-weaver/`) is semantically equivalent. The module's own javadoc declares it: `CoverageWeaver.java:23-32` ("Semantically equivalent to the AspectJ rule in `Coverage.aj`"), `SignatureFormatter.java:14-17` ("reproduces it byte-for-byte"). The production experiment `experimento-20260508` (190 APKs, JCA spec) ran `RV_INSTRUMENTATION_VARIANT=dexlib2` exclusively; all 2.78M coverage rows came from `coverage-weaver`-emitted `mop.Coverage.log()`. Reclassified NOT-NEEDED β.
- **`within(*..Log)` suffix-wildcard + `within(Coverage+)` `T+`-in-positive-within (§4.WW)** — Coverage.aj-specific extensions to §4.W; Coverage.aj absorbed, so these sub-forms have no consumer in the post-absorption pipeline. The simple `within(pkg..*)` form remains in-change as §4.W (other consumers exist in JCA and generic_new descriptors). Reclassified NOT-NEEDED β.

Round-8 result: **14 in-change closures (down from 20), ~1 015 LOC of production code (down from ~2 000)**, zero new dependencies on shipping an AspectJ runtime substrate, zero new cross-repo coordination beyond the single `namedPointcuts` schema field needed by §4.D. The matrix still archives with **zero `SILENT-GAP` rows**: the six dropped closures occupy NOT-NEEDED β rows with empirical evidence per row (see `deferred.md` §2.2.1). **Round-8 user-decision adjustment (2026-05-26)**: §4.E `execution(...)` real matcher is RESTORED as a full in-change closure (matcher + emitter) — defensive shipping so future specs that use `execution(...)` positively do not require re-opening the change.

The `Coverage.aj` source itself is NOT deleted — it remains in `rvsec-mop/src/main/resources/aspect/` as a semantic reference (the `CoverageWeaver` javadoc explicitly points at it as the equivalent specification). The decision on whether to physically archive `Coverage.aj` under `backup/` is deferred to the open-questions discussion (see "Open decisions for the user" in `docs/analise_sintese_macro.md` §6).

### From per-bug fixes to a grammar-anchored coverage matrix

This change moves from per-bug fixes to a **grammar-anchored coverage matrix**: one authoritative map of the AspectJ pointcut grammar against the dexlib2 parser/matcher/emitter, with pipeline-level demand counts from the four corpora and verdicts (COVERED / SILENT-GAP / EXPLICIT-NO-OP / NOT-NEEDED) for every production. The matrix becomes the contract that future closures reference.

**Scope: absorption-aware demand-driven (round-8).** Round-5 framed scope by nominal AspectJ family; round-6 substituted demand-driven scope (source-level) and shipped eight closures in-change; round-7 attempted total absorption of source-level non-zero-demand constructions (twenty closures); round-8 (this proposal) **scopes by pipeline-level demand** — the construction must reach the dexlib2 instrumenter to qualify for an in-change closure. The split is binary: any construction with `DemandCounter.countCompiledAj() ≥ 1` AT THE INSTRUMENTER STAGE ships **in-change**; constructions whose pipeline demand is zero (either via path α or path β) are NOT-NEEDED rows. No `Fix-now` ledger bucket survives.

The change therefore implements closures for **fourteen** constructs. Each closure flips one or more matrix rows from `SILENT-GAP` to `COVERED` with an enabled test asserting the post-fix behaviour against the corpus pattern that motivated it.

**In-change closures (round-8)**:

1. **Positive `within(typePattern)` matcher (simple form)** (13 jca + 13 generic_new = 26 pipeline-level sites) — reuse `matchesTypePattern` from `PointcutMatcher.java:343-358` for `pkg..*`. §4.W.
2. **`T+` in `call()` owner position** (~73 sites in generic_new) — extend the gh61 parameter-position subtype expansion to owner descriptor matching at `PointcutMatcher.java:153-157`. §4.O.
3. **`T+` in `call()` return position** (subset of generic_new T+ usage) — symmetric to §4.O for the return descriptor at the equivalent matcher branch. §4.R.
4. **`!target(T)` / `!args(T)` parser specialization** (32 sites: 28 `!target`, 4 `!args`, all generic_new) — extend `PointcutExpressionParser.parseUnary()` to specialize the negation of `target`/`args` type-matching beyond just `!within`. §4.N.
5. **`(T, ..)` trailing-mixed varargs** (14 jca + 2 generic_new) — `PointcutExpressionParser.isVarargs:271-273` accepts trailing-mixed forms by splitting `splitParams` into a head segment + trailing `..` marker; matcher matches the head positionally and accepts any remaining args. §4.V.
6. **Method-name glob `name*`** (~16 sites generic_new) — replace `expectedName.equals(actualName)` at `PointcutMatcher.java:161-167` with prefix-glob support (`endsWith("*")` → `startsWith(prefix)`). §4.X.
7. **`target(Type)` type-matching** (44 sites generic_new) — `PointcutMatcher.java:106-108` currently returns always-match for `TargetPC` regardless of declared `Type`. Implement subtype-aware type checking against the receiver register's declared type. §4.TT.
8. **`args(Type)` type-matching** (10 sites generic_new) — symmetric to §4.TT for the argument list; check declared types against the matched call's parameter descriptors. §4.AT.
9. **`staticinitialization(T+)` synthesis when `<clinit>` is absent** (6 sites generic_new) — synthesize a minimal `<clinit>` and weave the advice there. §4.Y.
10. **`after() throwing(...)` end-to-end weaver install** (2 sites generic_new + the discarded `AfterThrowingEmitter` plan) — install try-range + exception handler in the DEX so the after-throwing advice fires. §4.T.
11. **`BaseAspect.notwithin()` named-ref macro expansion** (1 jca + 1 generic_new) — the `notwithin` macro is an OR-chain of platform-namespace `!within(...)` filters declared in the project's `BaseAspect`. The §4.D symbol table resolves the name; the resolver then expands the OR-chain inline by composing `!within(...)` matchers per platform namespace. §4.B.
12. **`NamedRefPC` resolver via aspect-local symbol table** (consumer: §4.B's `BaseAspect.notwithin()`) — extend `AspectDescriptor` to carry a named-pointcut symbol table (`Map<String, PointcutExpression>`) populated by `DescriptorReader`; the `NamedRefPC` matcher resolves the reference against the table at evaluation time. Falls back to `commonPointcut` when the name is absent from the table; falls back to always-match with WARN log when both lookups fail. Round-8 narrowing: the symbol table need only hold the single `BaseAspect.notwithin()` reference per JCA descriptor — Coverage.aj's two named pointcuts (`excludedPackages()`, `traced()`) are absorbed with Coverage.aj. §4.D.
13. **`if(...)` AspectJ PCD via runtime-helper delegation** (8 sites generic_new) — round-7 planned in-weaver DEX lowering of the `<expr>` payload (~80 LOC parser + ~20 LOC codegen, judged unrealistic by 6/6 cross-LLM reviews). Round-8 substitutes runtime delegation: the weaver assigns a stable `ifId` per `if(...)` clause at weave time, emits `invoke-static MonitorRuntime.evaluateIf(ifId, args_boxed)` before the monitor invoke, and the monitor runtime provides a generated `evaluateIf(int, Object[])` switch-case (the per-ID switch arm holds the actual boolean expression). Eliminates the VerifyError surface area and the Java sub-grammar parser. §4.I.
14. **`execution(...)` real matcher + emitter** (1 aspect Coverage.aj + 24 jca + 28 generic_new source-level; 24 jca pipeline-level after JavaMOP compilation retains the execution clauses) — **RESTORED as full closure per round-8 user decision (2026-05-26)**, defensive shipping. Replace the `Match.empty(ex)` placeholder at `PointcutMatcher.matchExecution:307-313` with a real matcher that filters by method signature pattern (name + owner + params + return), respecting `*`/`..`/`T+`/wildcards already handled by `CallPC` semantics. Implement `ExecutionMatcherEmitter` (~150 LOC) wiring into `DexWeaver`'s method-execution weave path (different join-point selector than `call()` — emits at method entry for `before` / all return paths for `after`). The `execution(* *.*(..))` form matches every method execution; `execution(* Cipher.doFinal(..))` matches a specific method execution. §4.E.

## What Changes

**Matrix document (`docs/aspectj_grammar_coverage.md`)** — one row per AspectJ pointcut designator, advice form, type-pattern modifier, composition operator, advice-body reflective API element, aspect-declaration mechanic, and AspectJ runtime linkage requirement. For each row: normative syntax from the AspectJ Programming Guide §"Pointcuts" + AspectJ 5 quick reference, per-corpus demand counts (BOTH source-level via `DemandCounter.countMop()` AND pipeline-level via `DemandCounter.countCompiledAj()`) obtained via `DemandCounter`, parser/matcher/emitter state in dexlib2 anchored to `file:line`, and a verdict from the four-value vocabulary `{COVERED, SILENT-GAP, EXPLICIT-NO-OP, NOT-NEEDED}`. After round-8 absorption, the matrix SHALL contain **zero `SILENT-GAP` rows**: every row is `COVERED` (closure shipped in-change), `EXPLICIT-NO-OP` (UOE + assertion test; `around`/`proceed` only), or `NOT-NEEDED` (zero pipeline demand with documented rationale; path α has zero source demand, path β has source demand absorbed upstream).

The matrix SHALL cover **exactly** (not "at minimum") the following productions, enumerated by `AspectJDesignators.DESIGNATORS` in `grammar-tests`:

- **Classical pointcut designators (single-form rows)**: `call`, `execution`, `withincode`, `cflow`, `cflowbelow`, `if`, `condition`, `handler`, `get`, `set`, `staticinitialization`, `initialization`, `preinitialization`, `adviceexecution`, named-pointcut references.
- **`target` / `this` / `args` sub-semantic rows** (one row per sub-semantic): `target(name)`, `target(Type)`, `this(name)`, `this(Type)`, `args(name)`, `args(Type)`, `args(*, name, ..)`.
- **Within-family per-stage delegation rows**: `within(...)` positive simple `pkg..*`; `within(*..Log)` suffix-wildcard; `within(T+)` `T+`-inside-positive-within; `!within(...)`.
- **AspectJ 5 annotation pointcut designators**: `@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`.
- **Advice forms**: `before`, `after`, `after returning`, `after throwing`, `around`.
- **Type-pattern modifiers**: `T+` in `call()` param/owner/return/inside `!within(...)`; `*` wildcard; `..` standalone/trailing-mixed; dot-glob; single-level glob; arrays; inner-class qualifier.
- **SignaturePattern modifiers**: positive visibility, negated visibility, `static`, `final`, `throws ExceptionPattern`.
- **Composition operators**: `&&`, `||`, `!`, parentheses.
- **JavaMOP MOP-extensions**: `condition(...)`, `__STATICSIG` macro.
- **Advice-body reflective API**: `thisJoinPoint`, `thisJoinPointStaticPart`, `thisEnclosingJoinPointStaticPart`, `JoinPoint.getArgs()`, `JoinPoint.getSignature()` (+ `MethodSignature`/`ConstructorSignature`/`FieldSignature` subtype accessors), `JoinPoint.getTarget()`/`.getThis()`, `JoinPoint.getKind()`/`.getSourceLocation()`.
- **Around-advice mechanics**: `proceed(...)`.
- **Aspect declaration mechanics**: `aspect Foo { ... }`, `pointcut p(): ...` named declaration, abstract aspect + concrete subaspect, aspect inheritance, `declare precedence`, privileged aspect.
- **Runtime linkage**: `org.aspectj.lang.JoinPoint` family availability in the instrumented bytecode (post-round-8: this row's verdict is NOT-NEEDED β with `coverage-weaver` as the upstream absorber; the matrix still carries the row for completeness).

New AspectJ versions or new corpora add new rows; new always-match or malformed-descriptor paths in production code WITHOUT a corresponding row are forbidden.

**Grammar test corpus (`rvsec-android/rvsec-instrumentation-dexlib2/grammar-tests/`)** — a new Maven test-only submodule containing one test method per matrix row. After round-8 absorption, **no `@Disabled` annotation remains in `grammar-tests/`** (every matrix row is `COVERED`, `EXPLICIT-NO-OP`, or `NOT-NEEDED` — all three verdicts ship enabled passing tests).
