# Proposal: gh62-aspectj-grammar-coverage

## Why

The dexlib2 instrumenter (`rvsec-android/rvsec-instrumentation-dexlib2/`) has accumulated five incremental fixes (`gh52`, `gh56`, `gh57`, `gh59`, `gh61`), each targeting a single observed gap surfaced by a downstream symptom (a `VerifyError`, a missing `g2` event, a wide-slot binding bug). A cross-LLM artifact review of `gh61` (Codex GPT-5, DeepSeek, Gemini 2.5 Pro, Claude Opus 4.7) and a follow-up review of an earlier draft of this very change revealed that this reactive posture leaves **silent gaps** in production: pointcuts that parse without error, weave without crashing, and emit nothing — invisible without an external oracle.

Three classes of silent failure are confirmed against the current `HEAD` of `origin/modules`:

1. **Matcher always-match for unmodelled designators.** `PointcutMatcher.java:109-114` collapses `IfPC`, `NamedRefPC`, and `WithinPC` into `Match.empty(pe)` regardless of the underlying expression. Every pointcut that the parser cannot model becomes a `NamedRefPC` (`PointcutExpressionParser.java:131-132`), which means `this(...)`, `withincode(...)`, `cflow(...)`, `cflowbelow(...)`, `handler(...)`, `initialization(...)`, `preinitialization(...)`, `get(FieldPattern)`, `set(FieldPattern)`, and the AspectJ 5 annotation family (`@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`) are all silently always-match.
2. **Malformed-descriptor exact-match for partially-modelled forms.** `T+` in `call()` owner position (`PointcutMatcher.java:153-157`), `T+` in return type, `*` wildcard in method name (`PointcutMatcher.java:161-167`), and trailing-mixed `(T, ..)` varargs (`PointcutExpressionParser.java:271-273` — `isVarargs` only accepts `..` as the sole element) produce descriptors like `Ljava/io/OutputStream+;` or `Ljava/lang/..;` that never match anything.
3. **Silent emitter no-op.** `DexWeaver.java:560-566` has `case TRY_CATCH_WRAP: case REPLACE: break;` — `after() throwing(...)` plans are generated by `AfterThrowingEmitter` and silently discarded by the weaver with no log, no counter, no exception. The standard test surface — green bar against the JCA fixtures — cannot detect any of this.

Verified corpus demand (re-counted 2026-05-25 against `$RVSEC_HOME/rvsec/rvsec-mop/src/main/resources/{aspect,jca,generic,generic_new}/`, patterns that distinguish *pointcut* uses from *method-name* uses — see `DemandCounter` for exact regexes):

| Designator / form | aspect | jca | generic | generic_new |
|---|---:|---:|---:|---:|
| `get(FieldPattern)` / `set(FieldPattern)` *(true field-access pointcut)* | 0 | 0 | 0 | 0 |
| `(T, ..)` trailing-mixed varargs in `call()` | 0 | 14 | 0 | 4 |
| `T+` in `call()` owner/return | 0 | 0 | 0 | 135 |
| `execution(...)` (placeholder matcher) | 1 | 23 | 0 | 27 |
| `if(...)` (matcher always-match; emitter has `IfGuardEmitter` scaffold) | 8 | 16 | 0 | 37 |
| `this(...)` (any sub-semantic, as pointcut) | 0 | 0 | 0 | 0 |
| `target(...)` (binding + type) | 0 | 128 | 356 | 108 |
| `args(...)` (binding + type + mixed) | 0 | 159 | 96 | 47 |
| `adviceexecution()` (parsed as `NamedRefPC`) | 0 | 1 | 0 | 1 |
| `within(...)` positive | 24 | 13 | 0 | 13 |
| AspectJ 5 `@*` family (6 designators) | 0 | 0 | 0 | 0 |
| `after() throwing(...)` end-to-end | 0 | 0 | 0 | 2 |

Two prior baselines were corrected against the live grep: (a) earlier draft claimed 356/158 `get/set` field-access pointcuts in `generic/`/`generic_new/` — that count conflated `call(* Foo.get(...))` method-name calls with `get(FieldPattern)` field-access; corrected to **zero**. (b) v1 draft claimed `if(...) = 18 in generic_new`, `(T,..) = 4+ in jca`, `this(...) present in generic_new`, `execution(...) = 0 in jca`; verified counts are 37 / 14 / 0 / 23 respectively. The bucket assignments below reflect the corrected baseline.

This change moves from per-bug fixes to a **grammar-anchored coverage matrix**: one authoritative map of the AspectJ pointcut grammar against the dexlib2 parser/matcher/emitter, with demand counts from the four `.mop` corpora and verdicts (COVERED / SILENT-GAP / EXPLICIT-NO-OP / NOT-NEEDED) for every production. The matrix becomes the contract that future closures reference. No instrumenter production source code changes ship in this change — the deliverable is the matrix, an executable test corpus exercising every grammar row, and a scope ledger that schedules concrete closures as separate sub-changes. The only production-tree edit is a one-line `pom.xml` dependency-version bump (`smali-dexlib2` 3.0.8 → 3.0.9), gated by an empirical `dexdump` diff (see §0.3a in tasks).

GitHub Issue: [#62](https://github.com/PAMunb/rvsec/issues/62)

## What Changes

**Matrix document (`docs/aspectj_grammar_coverage.md`)** — one row per AspectJ pointcut designator, advice form, type-pattern modifier, and composition operator. For each row: normative syntax from the AspectJ Programming Guide §"Pointcuts" + AspectJ 5 quick reference, per-corpus demand counts obtained via a deterministic Java helper (`DemandCounter`, in the `grammar-tests` module — see below), parser/matcher/emitter state in dexlib2 anchored to `file:line`, and a verdict from the four-value vocabulary `{COVERED, SILENT-GAP, EXPLICIT-NO-OP, NOT-NEEDED}`. Verdicts MUST be anchored to evidence: every COVERED row cites a passing test in `grammar-tests/`; every SILENT-GAP row cites a `@Disabled` test naming the gap; every EXPLICIT-NO-OP row cites both an `UnsupportedOperationException`-asserting test AND the `file:line` of the no-op declaration.

The matrix SHALL cover **exactly** (not "at minimum") the following productions, enumerated by `AspectJDesignators.DESIGNATORS` in `grammar-tests`:

- **Classical pointcut designators (single-form rows)**: `call`, `execution`, `withincode`, `cflow`, `cflowbelow`, `if`, `handler`, `get`, `set`, `staticinitialization`, `initialization`, `preinitialization`, `adviceexecution`, named-pointcut references.
- **`target` / `this` / `args` sub-semantic rows** (one row per sub-semantic — the dexlib2 matcher diverges per sub-form):
  - `target(name)` value-binding (binds the receiver register; dominant use across `jca/`/`generic/` — e.g. `call(* Hashtable.get(Object)) && target(h) && args(o)`); `target(Type)` type-matching (matcher always-match at `PointcutMatcher.java:106-108`).
  - `this(name)` value-binding; `this(Type)` type-matching. Both currently fall into `NamedRefPC` always-match (`PointcutExpressionParser.java:131-132`); no `ThisPC` class exists.
  - `args(name)` value-binding; `args(Type)` type-matching; `args(*, name, ..)` mixed.
- **Within-family per-stage delegation rows**: `within(...)` positive (matcher always-match at `PointcutMatcher.java:109-114`, weaver-side filter required), `!within(...)` (matcher implements via `NotWithinPC`).
- **AspectJ 5 annotation pointcut designators**: `@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`.
- **Advice forms** (each as a row, because the dexlib2 weaver/emitter pipeline diverges per form): `before`, `after`, `after returning`, `after throwing`, `around`. Note: `returning(Id)` and `throwing(Id)` are advice modifiers (`after() returning(name): ...`), NOT pointcut designators — they appear only inside the advice-form rows, not as standalone matrix rows.
- **Type-pattern modifiers** (one row per position because matcher diverges per position):
  - `T+` in `call()` param position; `T+` in `call()` owner position; `T+` in `call()` return position; `T+` inside `!within(...)` (currently exact-match-after-strip at `PointcutMatcher.java:343-359`).
  - `*` wildcard; `..` standalone varargs; `..` trailing-mixed `(T, ..)` (distinct row); dot-glob (`..*`); single-level glob (`.*`); arrays (`T[]`, `T[][]`); inner-class (`Outer.Inner` vs `Outer$Inner`).
- **SignaturePattern modifiers**: positive visibility (`public`/`private`/`protected`), negated visibility (`!public`), `static`, `final`, `throws ExceptionPattern`. The matcher currently strips positive modifiers (`PointcutExpressionParser.java:200-215`); negated and non-visibility modifiers are unmodelled.
- **Composition operators**: `&&`, `||`, `!`, parentheses.

New AspectJ versions or new corpora add new rows; new always-match or malformed-descriptor paths in production code WITHOUT a corresponding row are forbidden.

**Grammar test corpus (`rvsec-android/rvsec-instrumentation-dexlib2/grammar-tests/`)** — a new Maven test-only submodule containing one test method per matrix row. Every COVERED row has a passing fixture today; every SILENT-GAP has a `@Disabled("gh62 SILENT-GAP: <one-line>")` fixture whose assertion describes the correct AspectJ behaviour. As future closures ship, the closure's commit removes the `@Disabled` annotation AND flips the matrix row's verdict atomically — partial flips are blocked by `MatrixIntegrityTest` (see §Bidirectional enforcement below).

**`DemandCounter` Java helper** (in `grammar-tests`) — replaces the originally-proposed inline shell grep recipe. `DemandCounter.count(Designator, Corpus)` walks `$RVSEC_HOME/rvsec/rvsec-mop/src/main/resources/{aspect,jca,generic,generic_new}/` with `Files.walk()` and a compiled `Pattern` per designator. Determinism is portable (no `bash -lc`, no `LC_ALL`, no shell quoting), `ProcessBuilder` is removed, and `MatrixIntegrityTest.testDemandCountsReproducible` invokes the helper directly. The matrix document quotes the `Pattern` per designator inline so reviewers can read it without opening Java code.

**Bidirectional enforcement** — `MatrixIntegrityTest` asserts BOTH directions:
- *Matrix → tests*: every COVERED row has an enabled test; every SILENT-GAP row has a `@Disabled` test (already in the original proposal).
- *Tests → matrix*: every enabled (non-`@Disabled`) test method in `grammar-tests/` resolves to a `COVERED` or `EXPLICIT-NO-OP` row (the latter is an enabled passing test asserting `UnsupportedOperationException` or equivalent); every `@Disabled` test resolves to a `SILENT-GAP` row; the skip count equals the `SILENT-GAP`-row count. A `@Disabled` test that begins to pass silently (gap closed accidentally), or an orphan test with no matrix row, breaks CI.

**Scope ledger (`openspec/changes/gh62-aspectj-grammar-coverage/ledger.md`)** — a three-bucket schedule with per-entry `Owner` and `Target milestone`. Bucket assignments are tentative pending the demand re-count in §5; the canonical assignment lives in tasks §1.3a/§1.3b/§1.3c.
- **Fix-now** (active demand in at least one corpus + scheduled this milestone): trailing-varargs `(T, ..)` in `call()` params (14 in `jca/`, 4 in `generic_new/`); `T+` in `call()` owner (135 in `generic_new/`); `T+` in `call()` return; `execution(...)` real matcher (23 in `jca/`, 27 in `generic_new/`); `BaseAspect.notwithin()` named-ref expansion; **`after() throwing(...)` end-to-end** (re-classified from EXPLICIT-NO-OP — `DexWeaver.java:560-566` discards the plan silently); `target(Type)` type-matching; `args(Type)` type-matching; `if(...)` matcher semantic evaluation (16 in `jca/`, 37 in `generic_new/` — the `IfGuardEmitter` scaffold is wired but the matcher remains always-match); `adviceexecution()` real semantics (currently parsed as `NamedRefPC` at `PointcutExpressionParser.java:131` → always-match; 1 hit each in `jca/` and `generic_new/`).
- **Follow-up** (real work but no current corpus demand, or non-blocking): `get(FieldPattern)`/`set(FieldPattern)` field-access matcher + emitter (zero demand after the corrected grep, but completeness); `this(name)` / `this(Type)` (zero corpus demand confirmed; no `ThisPC` class exists; matrix completeness only); `withincode(...)`; `cflow`/`cflowbelow`; `initialization(...)`/`preinitialization(...)`; AspectJ 5 `@*` family (6 designators, zero demand); positive `within(...)` matcher-side filter; `T+` inside `!within(...)` (exact-match-after-strip); SignaturePattern modifiers (positive visibility currently stripped; `!public`/`static`/`final`/`throws` unmodelled).
- **Deferred-by-design** (must remain unsupported with explicit assertion): `around` advice (`EmitterDispatch.java:61-65` + `EmitterDispatchTest.java:54-59`); `handler(...)` advice (no DEX-level analogue in scope). Note: `lock`/`unlock` and other AspectJ extensions are NOT in the ledger because they are NOT in the closed enumeration (zero demand AND outside the scope decision — see design.md OQ3).

**Bump `smali-dexlib2` 3.0.8 → 3.0.9** in `rvsec-android/rvsec-instrumentation-dexlib2/pom.xml:32`. The pin was set in the initial gh52 commit and never bumped; 3.0.9 is the latest published. The bump is an isolated commit (§0 in tasks) gated by `mvn package` AND a behavioural diff: 5 APKs from the INV-INS-31 baseline are re-instrumented pre/post-bump and `dexdump` output is diffed; non-trivial divergence reverts the bump within gh62 and tracks a separate `chore(deps)` issue. This is a runtime-dependency change (the shaded `instr-cli.jar` ships the new `smali-dexlib2` bytes); the §0.3a `dexdump` diff is the behavioural gate that pairs the bump with this otherwise documentation-only change.

**No other production instrumenter code changes ship in this change.** Sub-changes opened off the ledger ship their respective closures and reference back to gh62 in their proposals.

## Capabilities

### New Capabilities
*(none — the artefacts produced by this change live in `docs/`, `rvsec-android/.../grammar-tests/`, and `openspec/changes/<this>/`. No new domain capability is introduced.)*

### Modified Capabilities
- `instrumentation`: add an explicit requirement that the dexlib2 instrumenter's AspectJ surface is **documented as a grammar coverage matrix anchored to demand evidence**, and that any production parser/matcher/emitter behaviour MUST appear as a row in that matrix with a current verdict. The matrix is the contract; production code SHALL NOT introduce new always-match or malformed-descriptor paths without a corresponding row. This is a process invariant, enforced by `MatrixIntegrityTest` at every CI run.
