# Proposal: gh62-aspectj-grammar-coverage

## Why

The dexlib2 instrumenter (`rvsec-android/rvsec-instrumentation-dexlib2/`) has accumulated five incremental fixes (`gh52`, `gh56`, `gh57`, `gh59`, `gh61`), each targeting a single observed gap surfaced by a downstream symptom (a `VerifyError`, a missing `g2` event, a wide-slot binding bug). A cross-LLM artifact review of `gh61` (Codex GPT-5, DeepSeek, Gemini 2.5 Pro, Claude Opus 4.7) and a follow-up review of an earlier draft of this very change revealed that this reactive posture leaves **silent gaps** in production: pointcuts that parse without error, weave without crashing, and emit nothing — invisible without an external oracle.

Four classes of silent failure are confirmed against the current `HEAD` of `origin/modules`:

1. **Matcher always-match for unmodelled designators.** `PointcutMatcher.java:109-114` collapses `IfPC`, `NamedRefPC`, and `WithinPC` into `Match.empty(pe)` regardless of the underlying expression. Every pointcut that the parser cannot model becomes a `NamedRefPC` (`PointcutExpressionParser.java:131-132`), which means `this(...)`, `withincode(...)`, `cflow(...)`, `cflowbelow(...)`, `handler(...)`, `initialization(...)`, `preinitialization(...)`, `get(FieldPattern)`, `set(FieldPattern)`, and `adviceexecution()` are all silently always-match. The AspectJ 5 annotation family (`@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`) reaches the parser through a different failure mode: `PointcutExpressionParser.isIdentPart()` rejects `@` as an identifier character, so the parser raises `PointcutParseException` before reaching the `NamedRefPC` fallback. The end-state verdict is still SILENT-GAP (the gap surfaces as a parse-time exception that callers catch and downgrade), but the matcher always-match description does not apply to that family — the matrix rows for `@*` MUST cite the parser-crash anchor, not the matcher always-match anchor.
2. **Strict `.equals()` against unmodelled descriptors for partially-modelled forms.** `T+` in `call()` owner position (`PointcutMatcher.java:153-157` — `if (!expectedOwner.equals(actualOwner) && !cpsAwareOwnerMatch(...))`), `T+` in return type, `*` wildcard in method name (`PointcutMatcher.java:161-167` — `if (!expectedName.equals(mr.getName()))`), and trailing-mixed `(T, ..)` varargs (`PointcutExpressionParser.java:271-273` — `isVarargs` only accepts `..` as the sole element) fail to match because the matcher does literal string equality without expanding subtype/wildcard/varargs semantics. The earlier draft framed this as "malformed descriptors like `Ljava/io/OutputStream+;` being constructed" — that narrative is pedagogically convenient but not what the code does. The real defect is missing subtype/wildcard expansion before the `.equals()` (`cp.declaringType()` preserves the `+` suffix and feeds it unchanged into the comparison).
3. **Silent emitter no-op.** `DexWeaver.java:560-566` has `case TRY_CATCH_WRAP: case REPLACE: break;` — `after() throwing(...)` plans are generated by `AfterThrowingEmitter` and silently discarded by the weaver with no log, no counter, no exception. The standard test surface — green bar against the JCA fixtures — cannot detect any of this.
4. **Silent matcher/emitter gaps for MOP-specific constructs.** The dexlib2 instrumenter exists because AspectJ's offline weaver breaks on newer Android apps; for it to be a drop-in replacement, the constructs that the JavaMOP `.mop`/`.aj` corpora actually emit must have functional equivalents. A cross-LLM round-5 review re-grepped the four corpora and the compiled monitor bytecode (`MultiSpec_1RuntimeMonitor.java`) and surfaced eight high-demand constructs whose dexlib2 path is silently broken: (a) `condition(...)` MOP-extension guard — 74 sites across `jca/`+`generic_new/`, currently has no corresponding bytecode emit; (b) positive `within(typePattern)` — 28 sites (24 in `aspect/Coverage.aj` package filter), matcher always-true at `PointcutMatcher.java:109-114`; (c) `T+` in `call()` owner position — extensive use in `generic_new/`, gh61 only covered parameter position; (d) `!target(T)`/`!args(T)` — 32 sites in `generic_new/`, parser collapses to `NamedRefPC` always-match; (e) method-name glob `name*` — ~16 sites in `generic_new/`, matcher does literal `.equals()` at `PointcutMatcher.java:161-167`; (f) `__STATICSIG` JavaMOP macro — 3 sites in `generic_new/`, requires emitting a constant `Signature` populated from weave-time metadata; (g) `staticinitialization(T+)` synthesis when `<clinit>` is absent — 6 sites; (h) `after() throwing(...)` end-to-end weaver install — 2 sites, plan is generated but `DexWeaver.java:560-566` discards it silently. The advice-body reflective API family (`thisJoinPoint`, `Signature` subtypes) has **ZERO demand in `.mop` source** (re-grep confirmed: monitor bytecode `MultiSpec_1RuntimeMonitor.java` has zero `org.aspectj.*` references; the three apparent `thisJoinPoint` sites in `generic_new/` are `.aj` files synthesized by JavaMOP from the `__STATICSIG` macro). Reflective-API closure is therefore subsumed by `__STATICSIG` support — a 80-LOC inline constant, not a 600-LOC shipped runtime package.

The bucket assignments below reflect the corrected baseline.

This change moves from per-bug fixes to a **grammar-anchored coverage matrix**: one authoritative map of the AspectJ pointcut grammar against the dexlib2 parser/matcher/emitter, with demand counts from the four `.mop` corpora and verdicts (COVERED / SILENT-GAP / EXPLICIT-NO-OP / NOT-NEEDED) for every production. The matrix becomes the contract that future closures reference.

**Scope expansion (round-6 demand-driven D8)**: in addition to documenting the surface, this change implements closures for the eight constructs whose corpus demand is highest and whose dexlib2 path is silently broken. Round-5 framed scope by nominal AspectJ family (Reflective API + Matcher Correctness); round-6 cross-LLM review (opus47_deep + four supporting reports) empirically verified that the nominal families miss ~70% of high-traffic gaps. The redesign drops gold-plating (600 LOC of shipped `aspectjlang.*` classes for 0 demand sites; standalone `TargetPC`/`ArgsPC` for 0 demand sites; `!cflow`/`!cflowbelow`/`!if`/`!handler` parser specialization for 0 demand sites) and substitutes targeted closures for the eight measured gaps:

1. **`condition(...)` MOP-extension guard** (74 sites: 64 jca, 10 generic_new) — emit a boolean guard before the monitor invoke; the JavaMOP semantics for `condition(<expr>)` is "evaluate `<expr>` in the advice context; skip the monitor dispatch if false". §4.G in tasks.
2. **Positive `within(typePattern)` matcher** (28 sites: 24 aspect/Coverage.aj, 2 jca, 2 generic_new) — reuse `matchesTypePattern` from `NotWithinPC:343-359` to filter `classDef` FQN against the pattern; currently always-true at `PointcutMatcher.java:109-114`. §4.W.
3. **`T+` in `call()` owner position** (extensive demand in generic_new) — extend the gh61 parameter-position subtype expansion to owner descriptor matching at `PointcutMatcher.java:153-157`. §4.O.
4. **`!target(T)` / `!args(T)` parser specialization** (32 sites: 28 `!target`, 4 `!args`, all in generic_new) — extend `PointcutExpressionParser.parseUnary()` to specialize the negation of `target`/`args` type-matching beyond just `!within`. §4.N.
5. **Method-name glob `name*`** (~16 sites in generic_new) — replace `expectedName.equals(actualName)` at `PointcutMatcher.java:161-167` with prefix-glob support (`endsWith("*")` → `startsWith(prefix)`). §4.X.
6. **`__STATICSIG` JavaMOP macro support** (3 sites in generic_new: `Collection_HashCode.mop`, `Serializable_NoArgConstructor.mop`, `URLConnection_OverrideGetPermission.mop`) — emit an inline constant `Signature` populated from weave-time metadata; subsumes the reflective-API row because real demand is exhausted by `__STATICSIG`. §4.S.
7. **`staticinitialization(T+)` synthesis when `<clinit>` is absent** (6 sites in generic_new) — synthesize a minimal `<clinit>` and weave the advice there. §4.Y.
8. **`after() throwing(...)` end-to-end weaver install** (2 sites in generic_new, plus the AfterThrowingEmitter plan currently discarded at `DexWeaver.java:560-566`) — install try-range + exception handler in the DEX so the after-throwing advice fires. §4.T.

Plus one zero-cost matcher fix bundled because the empirical verification surfaced the trivial path: **`NamedRefPC` resolves against `commonPointcut`** (the existing field in `AspectDescriptor`) — no new schema needed. §4.D in tasks (~30 LOC).

Rows flip SILENT-GAP → COVERED in-change for: `condition(...)`, `within(typePattern)` positive, `T+` in owner, `!target(T)`/`!args(T)`, method-name glob `name*`, `__STATICSIG`, `staticinitialization` synthesis, `after() throwing(...)`, named-pointcut reference (resolved via `commonPointcut`). The remaining SILENT-GAP rows (trailing-varargs `(T, ..)`, `T+` in return position, `execution(...)` real matcher, `if(...)` semantic evaluation, `target(Type)`/`args(Type)` type-matching, `adviceexecution()`, `BaseAspect.notwithin()` expansion, `withincode`/`cflow`/`cflowbelow`/`initialization`/`preinitialization`, AspectJ 5 `@*` family, signature-pattern modifiers, `T+` inside `!within`, `thisJoinPointStaticPart`/`thisEnclosingJoinPointStaticPart` bindings, abstract aspect, aspect inheritance, privileged aspect) remain in the ledger as Fix-now or Follow-up entries — each is documented but not closed in-change.

The smali property bump (`smali-dexlib2` 3.0.8 → 3.0.9) ships in §0 gated by an empirical `dexdump` diff (see §0.3a in tasks).

## What Changes

**Matrix document (`docs/aspectj_grammar_coverage.md`)** — one row per AspectJ pointcut designator, advice form, type-pattern modifier, composition operator, advice-body reflective API element, aspect-declaration mechanic, and AspectJ runtime linkage requirement. For each row: normative syntax from the AspectJ Programming Guide §"Pointcuts" + AspectJ 5 quick reference, per-corpus demand counts obtained via a deterministic Java helper (`DemandCounter`, in the `grammar-tests` module — see below), parser/matcher/emitter state in dexlib2 anchored to `file:line`, and a verdict from the four-value vocabulary `{COVERED, SILENT-GAP, EXPLICIT-NO-OP, NOT-NEEDED}`. Verdicts MUST be anchored to evidence: every COVERED row cites a passing test in `grammar-tests/`; every SILENT-GAP row cites a `@Disabled` test naming the gap; every EXPLICIT-NO-OP row cites both an `UnsupportedOperationException`-asserting test AND the `file:line` of the no-op declaration.

The matrix SHALL cover **exactly** (not "at minimum") the following productions, enumerated by `AspectJDesignators.DESIGNATORS` in `grammar-tests`:

- **Classical pointcut designators (single-form rows)**: `call`, `execution`, `withincode`, `cflow`, `cflowbelow`, `if`, `handler`, `get`, `set`, `staticinitialization`, `initialization`, `preinitialization`, `adviceexecution`, named-pointcut references.
- **`target` / `this` / `args` sub-semantic rows** (one row per sub-semantic — the dexlib2 matcher diverges per sub-form):
  - `target(name)` value-binding (binds the receiver register; dominant use across `jca/`/`generic/` — e.g. `call(* Hashtable.get(Object)) && target(h) && args(o)`); `target(Type)` type-matching (matcher always-match at `PointcutMatcher.java:106-108`).
  - `this(name)` value-binding; `this(Type)` type-matching. Both currently fall into `NamedRefPC` always-match (`PointcutExpressionParser.java:131-132`); no `ThisPC` class exists.
  - `args(name)` value-binding; `args(Type)` type-matching; `args(*, name, ..)` mixed.
- **Within-family per-stage delegation rows**: `within(...)` positive (matcher always-match at `PointcutMatcher.java:109-114`, weaver-side filter required), `!within(...)` (matcher implements via `NotWithinPC`).
- **AspectJ 5 annotation pointcut designators**: `@annotation`, `@target`, `@this`, `@args`, `@within`, `@withincode`.
- **Advice forms** (each as a row, because the dexlib2 weaver/emitter pipeline diverges per form): `before`, `after`, `after returning`, `after throwing`, `around`. Note: `returning(Id)` and `throwing(Id)` are advice modifiers (`after() returning(name): ...`), NOT pointcut designators — they appear only inside the advice-form rows, not as standalone matrix rows.
- **Type-pattern modifiers** (one row per position because matcher diverges per position):
  - `T+` in `call()` param position; `T+` in `call()` owner position; `T+` in `call()` return position; `T+` inside `!within(...)` (currently exact-match-after-strip at `PointcutMatcher.java:343-359`).
  - `*` wildcard; `..` standalone varargs; `..` trailing-mixed `(T, ..)` (distinct row); dot-glob (`..*`); single-level glob (`.*`); arrays (`T[]`, `T[][]`); inner-class (`Outer.Inner` vs `Outer$Inner`).
- **SignaturePattern modifiers**: positive visibility (`public`/`private`/`protected`), negated visibility (`!public`), `static`, `final`, `throws ExceptionPattern`. The matcher currently strips positive modifiers (`PointcutExpressionParser.java:200-215`); negated and non-visibility modifiers are unmodelled.
- **Composition operators**: `&&`, `||`, `!`, parentheses.
- **Advice-body reflective API** (behavioural-parity rows — what the advice body reads at runtime; if dexlib2 weaves the advice but does not populate these the monitor silently produces empty events): `thisJoinPoint` binding; `thisJoinPointStaticPart` binding; `thisEnclosingJoinPointStaticPart` binding; `JoinPoint.getArgs()`; `JoinPoint.getSignature()` (+ `MethodSignature` / `ConstructorSignature` / `FieldSignature` subtype accessors `.getName()` / `.getDeclaringType()` / `.getParameterTypes()` / `.getReturnType()`); `JoinPoint.getTarget()` / `.getThis()`; `JoinPoint.getKind()` / `.getSourceLocation()`.
- **Around-advice mechanics**: `proceed(...)` keyword inside around body (one row; consistent with `around` itself being EXPLICIT-NO-OP at the emitter level — a future closure of `around` MUST simultaneously close this row).
- **Aspect declaration mechanics**: `aspect Foo { ... }` declaration syntax; named-pointcut declaration `pointcut p(): ...` (distinct from named-pointcut *reference* under classical designators); abstract-aspect + concrete-subaspect pattern (the JavaMOP `BaseAspect` idiom relies on this); aspect inheritance (`aspect Bar extends Foo`); `declare precedence: A, B;` (advice ordering across aspects — without it, two aspects matching the same join point emit events in non-deterministic order); privileged aspect (access to private members of woven types).
- **Runtime linkage**: `org.aspectj.lang.JoinPoint` (and `JoinPoint.StaticPart`, `Signature` subtypes) class availability in the instrumented bytecode — without this row the dependent advice-body rows have no runtime substrate.

New AspectJ versions or new corpora add new rows; new always-match or malformed-descriptor paths in production code WITHOUT a corresponding row are forbidden.

**Grammar test corpus (`rvsec-android/rvsec-instrumentation-dexlib2/grammar-tests/`)** — a new Maven test-only submodule containing one test method per matrix row. Every COVERED row has a passing fixture today; every SILENT-GAP has a `@Disabled("gh62 SILENT-GAP: <one-line>")` fixture whose assertion describes the correct AspectJ behaviour. As future closures ship, the closure's commit removes the `@Disabled` annotation AND flips the matrix row's verdict atomically — partial flips are blocked by `MatrixIntegrityTest` (see §Bidirectional enforcement below).

**`DemandCounter` Java helper** (in `grammar-tests`) — replaces the originally-proposed inline shell grep recipe. `DemandCounter.count(Designator, Corpus)` walks `$RVSEC_HOME/rvsec/rvsec-mop/src/main/resources/{aspect,jca,generic,generic_new}/` with `Files.walk()` and a compiled `Pattern` per designator. Determinism is portable (no `bash -lc`, no `LC_ALL`, no shell quoting), `ProcessBuilder` is removed, and `MatrixIntegrityTest.testDemandCountsReproducible` invokes the helper directly. The matrix document quotes the `Pattern` per designator inline so reviewers can read it without opening Java code.

**Bidirectional enforcement** — `MatrixIntegrityTest` asserts BOTH directions:
- *Matrix → tests*: every COVERED row has an enabled test; every SILENT-GAP row has a `@Disabled` test (already in the original proposal).
- *Tests → matrix*: every enabled (non-`@Disabled`) test method in `grammar-tests/` resolves to a `COVERED` or `EXPLICIT-NO-OP` row (the latter is an enabled passing test asserting `UnsupportedOperationException` or equivalent); every `@Disabled` test resolves to a `SILENT-GAP` row; the skip count equals the `SILENT-GAP`-row count. A `@Disabled` test that begins to pass silently (gap closed accidentally), or an orphan test with no matrix row, breaks CI.

**Scope ledger (`openspec/changes/gh62-aspectj-grammar-coverage/ledger.md`)** — a three-bucket schedule with per-entry `Owner` and `Target milestone`. Bucket assignments are tentative pending the `DemandCounter`-driven re-count in §3.4 (executed BEFORE matrix population in §5); the canonical assignment lives in tasks §1.3a/§1.3b/§1.3c.

The four-value verdict vocabulary is unchanged. Round-5 review eliminated the SILENT-GAP-permanent sub-bucket: `handler(...)` and `declare precedence` are now classified `NOT-NEEDED` via INV-INS-89 path β (handler joinpoints have no DEX-level analogue — the production "absorbs" them at the source level before reaching the matcher; `declare precedence` is a runtime ordering property of the monitor dispatch loop, not a weaver concern — also out-of-pipeline). `aspect Foo { ... }` and `pointcut p(): ...` are likewise `NOT-NEEDED` path β: the dexlib2 pipeline reads JSON `AspectDescriptor` produced upstream by the JavaMOP toolchain (`DescriptorReader.java`); `.aj` source never reaches `PointcutExpressionParser`. These four rows still appear in the matrix with `Verdict = NOT-NEEDED`, carry enabled passing tests asserting equivalent-descriptor production regardless of upstream syntax, and do NOT appear in the ledger (NOT-NEEDED rows are not open work; they are bucket-free by construction).

- **Fix-now** (active demand in at least one corpus + scheduled in a future sub-change): trailing-varargs `(T, ..)` in `call()` params; `T+` in `call()` return; `execution(...)` real matcher; `BaseAspect.notwithin()` named-ref expansion; `target(Type)` type-matching (the binding `target(name)` form is in-change via the round-6 `__STATICSIG`-adjacent paths; the type-matching `target(Type)` remains scheduled); `args(Type)` type-matching; `if(...)` matcher semantic evaluation (the `IfGuardEmitter` scaffold is wired via `EmitterDispatch.java:70-74` but the matcher remains always-match); `adviceexecution()` real semantics (currently parsed as `NamedRefPC` at `PointcutExpressionParser.java:131` → always-match).
- **Follow-up** (real work but no current corpus demand, or non-blocking): `get(FieldPattern)`/`set(FieldPattern)` field-access matcher + emitter (zero demand after corrected grep, completeness); `this(name)` / `this(Type)` (zero corpus demand confirmed; no `ThisPC` class — matrix completeness only); `withincode(...)`; `cflow`/`cflowbelow`; `initialization(...)`/`preinitialization(...)`; AspectJ 5 `@*` family (6 designators, zero demand); standalone `target(name)`/`args(name)` matching without `&&`-composition (zero demand — all corpus uses are `&&`-composed with `call()`); `!cflow`/`!cflowbelow`/`!if`/`!handler` parser specialization (zero demand — only `!within`/`!target`/`!args` appear in corpora); `T+` inside `!within(...)` (exact-match-after-strip); SignaturePattern modifiers (positive visibility currently stripped; `!public`/`static`/`final`/`throws` unmodelled); `thisJoinPoint`/`thisJoinPointStaticPart`/`thisEnclosingJoinPointStaticPart` bindings beyond the `__STATICSIG` path (zero source demand confirmed — monitor bytecode has zero `org.aspectj.*` references); aspect inheritance (`aspect Bar extends Foo`); abstract-aspect + concrete-subaspect pattern (zero demand in corpora today but relevant for `BaseAspect` idiom); privileged aspect; full shipped `org.aspectj.lang.*` runtime classes (deferred — `__STATICSIG` inline-constant approach covers measured demand); **AspectJ weaver parity diff vs. AJC offline reference** (gold-standard behavioural oracle for SILENT-GAP `@Disabled` tests — surfaces closures that pass the disabled-test assertion but diverge from real AspectJ; deferred per cross-LLM review as oracle-of-behaviour, not oracle-of-grammar).
- **Deferred-by-design** (production code raises `UnsupportedOperationException` AND a passing test asserts the throw — INV-INS-89-compliant `EXPLICIT-NO-OP`): `around` advice (`EmitterDispatch.java:61-65` + `EmitterDispatchTest.java:54-59`); `proceed(...)` keyword in around body (EXPLICIT-NO-OP consistent with `around` itself — the around row's UOE covers it by reflection).

The eight round-6 in-change closures (`condition(...)`, positive `within(typePattern)`, `T+` in owner, `!target(T)`/`!args(T)`, method-name glob `name*`, `__STATICSIG`, `staticinitialization` synthesis, `after() throwing(...)`) and the namedPointcut resolver via `commonPointcut` are **NOT in the ledger** because they ship as COVERED rows in this change (see §"Scope expansion" above).

Note: `lock`/`unlock` and other AspectJ extensions are NOT in the ledger because they are NOT in the closed enumeration (zero demand AND outside the scope decision — see design.md OQ3). Per-clauses, ITDs, `declare warning/error/soft`, annotation-style aspects, and generics in type patterns are AUSENTE-JUSTIFICADO (design.md OQ4) — also outside the closed enumeration.

**Bump `smali-dexlib2` 3.0.8 → 3.0.9** in `rvsec-android/rvsec-instrumentation-dexlib2/pom.xml:32`. The pin was set in the initial gh52 commit and never bumped; 3.0.9 is the latest published. The bump is an isolated commit (§0 in tasks) gated by `mvn package` AND a behavioural diff: 5 APKs from the INV-INS-31 baseline are re-instrumented pre/post-bump and `dexdump` output is diffed; non-trivial divergence reverts the bump within gh62 and tracks a separate `chore(deps)` issue. This is a runtime-dependency change (the shaded `instr-cli.jar` ships the new `smali-dexlib2` bytes); the §0.3a `dexdump` diff is the behavioural gate that pairs the bump with this otherwise documentation-only change.

**Other production code changes ship in this change** — see §"Scope expansion" above. Specifically, `advice-emitter/` gains the `condition(...)` guard emit (§4.G), the `__STATICSIG` inline-constant emit (§4.S), the `after() throwing(...)` try-range/handler install (§4.T), and the `staticinitialization` synthesis (§4.Y); `pointcut-engine/` gains positive `within(typePattern)` matching (§4.W), `T+` in owner expansion (§4.O), method-name glob (§4.X), `!target(T)`/`!args(T)` parser specialization (§4.N), and the `NamedRefPC` resolver against `commonPointcut` (§4.D). Sub-changes opened off the ledger ship the remaining closures and reference back to gh62 in their proposals.

## Capabilities

### New Capabilities
*(none — the artefacts produced by this change live in `docs/`, `rvsec-android/.../grammar-tests/`, `rvsec-android/.../advice-emitter/`, `rvsec-android/.../pointcut-engine/`, and `openspec/changes/<this>/`. No new domain capability is introduced; existing `instrumentation` capability is extended.)*

### Modified Capabilities
- `instrumentation`: three additions.
  1. The dexlib2 instrumenter's AspectJ surface SHALL be **documented as a grammar coverage matrix anchored to demand evidence**; any production parser/matcher/emitter behaviour MUST appear as a row in that matrix with a current verdict. The matrix is the contract; production code SHALL NOT introduce new always-match or malformed-descriptor paths without a corresponding row. Enforced by `MatrixIntegrityTest` at every CI run.
  2. The dexlib2 instrumenter SHALL implement **demand-driven closures for eight high-traffic constructs** measured in the four corpora (`condition(...)` guard emit, positive `within(typePattern)` matching, `T+` in `call()` owner, `!target(T)`/`!args(T)` parser specialization, method-name glob `name*`, `__STATICSIG` macro support, `staticinitialization` synthesis, `after() throwing(...)` end-to-end install). Each closure flips its matrix row from SILENT-GAP to COVERED with an enabled test asserting the post-fix behaviour against the corpus pattern that motivated it.
  3. The dexlib2 pointcut matcher SHALL resolve **named-pointcut references** against the existing `AspectDescriptor.getCommonPointcut()` field; the `NamedRefPC` always-match fallback is retained only for references that do not resolve, and a warn-level log records each unresolved reference for future ledger work.

**Pipeline impact:**

- `grammar-tests/` is excluded from the `instr-cli.jar` shade plugin; the matrix and ledger documents do not enter the jar.
- **`instr-cli.jar` ships behaviour changes** for the eight demand-driven gap closures. Pre-change `condition(...)` was silently inert (no guard, monitor always invoked); post-change the boolean guard short-circuits the monitor dispatch when `<expr>` evaluates to false. Pre-change positive `within(typePattern)` matched everywhere (always-true); post-change it filters `classDef` FQN against the pattern. Pre-change `T+` in `call()` owner failed literal-equals; post-change subtype expansion (from gh61) covers owner descriptors. Pre-change `!target(T)`/`!args(T)` collapsed to `NamedRefPC` always-match; post-change `parseUnary` specialization yields proper negation. Pre-change method-name glob `name*` did literal equals; post-change it does prefix-match. Pre-change `__STATICSIG` was unrecognized (advice body referenced an undefined symbol); post-change the macro is expanded to an inline constant `Signature`. Pre-change `staticinitialization(T+)` matched classes with an existing `<clinit>` only; post-change a minimal `<clinit>` is synthesized when absent. Pre-change `after() throwing(...)` plans were discarded silently; post-change try-range + handler are installed. The nine changes flip ~9 matrix rows from SILENT-GAP to COVERED. Behavioural equivalence on the pre-existing surface (call-pointcut matching, before/after weaving, register allocation post-gh61) is gated by the smali bump's `dexdump` diff (§0.3a, 5 APKs from the INV-INS-31 baseline) AND by the existing per-module test bars (`pointcut-engine`, `advice-emitter`, `dex-mutator`, `coverage-weaver`).
