# Stage-4 counterpart: native NDJSON trace reader, gzip at collection, heartbeat tag in the capture allowlist

GitHub Issue: #94

## Why

Stage 4 of the APE-RV re-architecture (`ape`, change `rearch-04-step-ndjson-telemetry`, artifacts approved 2026-08-03) replaces the `[APE-STEP]` / `[APE-OUTCOME]` / `[APE-LLM-TEL]` `key=value` line family with one NDJSON `StepRecord` per step. The `.trace` **is** the NDJSON and is never rewritten: there is deliberately no NDJSON→legacy converter, because reconstructing the unescaped `key=value` family over the primary artifact would make the file everyone opens a derived reconstruction and would re-import the line-breaking defect the new serializer exists to remove. The consequence for this repository is direct — the one production consumer of the legacy family, `clock_logcat_join.py`, reads a format that will no longer be produced, and nothing else on this side can read the new one. Without a native reader, the analysis path goes dark the moment the stage-4 jar is deployed.

The second reason is a coupling that fails silently rather than loudly. Stage 4 adds a write-only logcat heartbeat (one `Log.i` per step) whose purpose is to put step and violation on the same clock, so that `clock_logcat_join.py` can stop reconstructing the device's UTC offset. But `LogcatManager.start_capture` does not dump the ring buffer after the run — it streams `adb logcat -v threadtime -s RVSEC:V RVSEC-COV:V` for the run's duration, a strict tag allowlist, with the buffer cleared at start. A heartbeat written under any tag outside that allowlist is filtered out **at the device** and never reaches the file the join reads. The mechanism would be inert, and the inertness would be invisible: the join would keep working on its old reconstruction while the heartbeat wrote to nothing. That is the failure class stage 4 exists to end, reproduced on the analysis path. The tag therefore has to be added here, and the two invariants that pin the capture command byte-for-byte have to be amended with it.

## What Changes

- **New** `modules/aperv-tool/src/aperv_tool/analysis/trace_ndjson.py`: a read-only, streaming NDJSON reader. It resolves the `ACT` / `STATE` dictionary references, materializes the fields the sink omits at their documented defaults, re-derives `activity_has_mop` on the step side from the record's `ACT` entry and on the outcome side via `out.target` → `STATE.act` → `ACT.mop`, expands the run-relative `t` to epoch milliseconds via `RUN_START.t0`, and yields one typed row per step with its `dec`, `llm[]` and `out` sections already joined — so the three-way join by `step=` ceases to exist for every consumer. It performs no format conversion and never runs on the collection path.
- **gzip at collection** in `tools/aperv/tool.py`: after the existing empty-trace check, compress the raw capture to `<trace>.ndjson.gz`. Non-fatal (a failure logs a WARNING and leaves the uncompressed trace in place), and it runs on the timeout path too — timeout is the normal exit for an exploration run, so collection must not be skipped on it. `task.result.trace_file` stays byte-for-byte the raw capture.
- **BREAKING** — `analysis/clock_logcat_join.py` migrates onto the reader: the `[APE-STEP]` regex is replaced by reader rows, and `_align_clocks()` together with the whole UTC-offset reconstruction (the three year candidates, the quarter-hour rounding, the anchor selection, and the `alignment_residual_ms` field of `RunJoin`) is **deleted, not disabled**. With step and violation in the same file on the same clock, the reconstruction has nothing left to reconstruct. This changes the module's public result shape (`RunJoin` loses a field), which is why it is marked breaking.
- The deletion above carries an **ordering precondition**, not a caveat: it lands only after a captured run is shown to contain heartbeat lines. Deleting a working fallback in favour of a mechanism never observed end to end is the same silent-inertness class described in Why. This is `event-sink` INV-SNK-14 on the jar side, and it is encoded as a task ordering constraint rather than as design prose.
- **The heartbeat tag reaches the capture**: `ApeRvHb` — the tag the jar's design D-6 names, adopted verbatim so the two repositories cut the string once — is added to `LogcatManager.default_tags`. It is 7 characters, inside the device's 23-character tag bound. The tag is appended after the two existing entries, so `RVSEC:V RVSEC-COV:V` keep their position and order.
- **BREAKING** — the two invariants that pin the capture command byte-for-byte are amended to the new baseline `adb -s <serial> logcat -v threadtime -s RVSEC:V RVSEC-COV:V ApeRvHb:V`: **INV-CORE-37** (which spells the baseline string literally) and **INV-PLT-21** (which requires `LogcatComponent` to start capture with the baseline tag set when `logcat_diagnostics` is false). The issue names only INV-PLT-21; INV-CORE-37 is the one that carries the literal string, and leaving it unamended would make the change fail its own guard test. Both new forms are pinned by test.
- **The frozen-corpus carve-out is recorded as normative**: `scripts/cmpm_stratify.py`, `scripts/analyze_cmpv2_llm.py`, `experimento-cal/scripts/*`, `experimento-20260721/scripts/*` and `calibracao/*` keep parsing the legacy `[APE-*]` format and are not migrated, adapted or deleted. They are not compatibility shims — they are the readers of a dataset that is finished and will not be regenerated. P3 governs superseded *implementation*, not analysis code over frozen data. The distinction is operational: `clock_logcat_join.py` migrates because it must read *new* traces; these never will. Stating this in the spec is what stops a later cleanup sweep from reading them as shims. `coverage_dump.py` is likewise untouched: it reads only the `[APE-RV] UICOV` / `UICOV-ACT` lines, which stage 4 does not modify.
- **No exit contract** (owner decision D5 on the jar side): no code path on this side reads, validates or acts on `RUN_END`. No sentinel check, no task-status change, no retry logic. Truncated-run detection stays post-hoc over trace and logcat timestamps, exactly as today.

## Capabilities

### New Capabilities

None. Every deliverable lands inside an existing capability.

### Modified Capabilities

- `aperv`: the execution-flow requirement gains the gzip collection step; a new requirement covers the native NDJSON reader and the `clock_logcat_join.py` migration; a new requirement records the frozen-corpus carve-out as normative.
- `core`: `LogcatManager.default_tags` gains the heartbeat tag, and INV-CORE-37's byte-identical baseline command is amended to match.
- `platform`: INV-PLT-21 is amended so the baseline tag set `LogcatComponent` passes when `logcat_diagnostics` is false is the new three-tag set.

## Impact

**Modules.** `aperv-tool` (new `analysis/trace_ndjson.py`; `analysis/clock_logcat_join.py` rewritten onto it; `tools/aperv/tool.py` gains the gzip step), `rv-android-core` (`util/android/logcat_manager.py`, `default_tags`), `rv-platform` (`components/logcat.py` — no code change expected, but its INV-PLT-21 guard tests pin the emitted command and must be updated with the new baseline).

**Requirements.** FR11 and FR13 (violation and coverage analysis over recorded artifacts) and NFR03 for the reader and the join; FR18 and FR19 (tool execution) for the collection step; FR33 and FR34 (logging and diagnostics) for the tag allowlist; NFR06 for the reader's diagnostics over malformed records.

**Cross-repository dependency.** The wire format is defined jointly and cut once: `ape` change `rearch-04-step-ndjson-telemetry`, whose `event-sink` spec is the authority for the `StepRecord` schema, the dictionary encoding, the omitted-default rules, and the heartbeat's tag and payload. Its task 5.2a names this change as the counterpart that adds the tag to the allowlist; its task 8.3 is the mirror of the ordering precondition above. Group 8 of that change is the work landing here, and its acceptance gate (regenerating the 2026-07-24 calibration report from a new-format trace, task 9.2) is reachable only through the reader delivered here.

**Scheduling constraint for `gh97-rearch-ab-gate`.** The A/B capture has a window: **before stage 4 lands, or after `trace_ndjson.py` exists** — not in between. Stage 4 freezes the comparison scaffold's trace readers on the legacy `[APE-*]` format, so the step-level panel (step counts, `src_*` attribution, actions by type) goes dark for any run captured against a stage-4 jar until the reader is in place. The primary outcomes (`cov_*`, `mop_unique`, `mop_total`) survive either way, because they come from `tasks.json` and from logcat rather than from the trace. This is recorded here because it is a cross-change scheduling fact and `gh97` has no artifacts yet to carry it.

**Not in scope.** The `gh95-thin-python-arms` debt is untouched: archiving `gh88` pushed the calibration arm tier and `LLM_ARM_KEYS` into the main `aperv` spec, and removing them belongs to `gh95`. Where this change's `aperv` delta touches neighbouring spec regions, it leaves those constructs alone. The throughput gate (INV-SNK-13) is owner-executed on the jar side and is not a deliverable here. Acceptance of the heartbeat's presence in a captured run requires a device and is therefore an apply-phase obligation executed through `rv-experiment`/`rv-platform`, which own the emulator lifecycle.
