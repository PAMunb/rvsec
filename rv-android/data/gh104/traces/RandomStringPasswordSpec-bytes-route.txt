# The bridge doing the one job it exists for, with a source the set actually produces.
#
# RandomStringPassword.mop carries `randomized` across two JDK conversions,
# Object -> String -> char[], and the only consumer of `randomized` over a char[] in
# the whole set is PBEKeySpecSpec.c1's password read. The committed trace of this file
# passes a String literal, whose guard is false, so no trace ever exercised the
# propagation. This one does: the array comes from an observed SecureRandom.
#
# What it measures is that the conversion does not carry what the predicate claims.
# `String.valueOf(Object)` on a byte[] calls Object.toString(), which returns the
# identity string -- measured, '[B@726f3b58' -- so the char[] the bridge marks
# `randomized` holds a heap identity hash and no key material at all. On the pre-image
# this program is SILENT: the mark propagates and PBEKeySpecSpec accepts the password.
# That silence is a false negative, and it is what the pass removes by deleting the
# bridge's four predicate sites.
#
# The salt comes from generateSeed rather than a second nextBytes on purpose: two
# nextBytes calls are what SecureRandomSpec-nextbytes-twice.txt already measures, and
# carrying that repair in here would classify this trace on someone else's change.
bind buf = bytes(16)
SecureRandom.getInstance("SHA1PRNG") -> r
r.nextBytes(buf)
String.valueOf(buf) -> s
s.toCharArray() -> pw
r.generateSeed(16) -> salt
new PBEKeySpec(pw, salt, 10000, 128) -> spec
spec.clearPassword()
