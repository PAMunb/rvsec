# The other half of the F2 window task 4.12 opened, and the producer that had no witness.
#
# `generatedKey` has two producers left on the old substrate after task 4.12:
# KeyGenerator.generateKey() (KeyGenerator.cryptsl:57), witnessed by
# SecretKeySpec-keygen-iv.txt, and KeyStore.getKey() (KeyStore.cryptsl:97), witnessed here.
# Both are migrated by task 4.14 and both readers -- CipherSpec.i2 and SecretKeySpec.e1 --
# have been on the new store since tasks 4.1 and 4.12.
#
# Measured on the starting tree, before the edit: this program drew one
# IVPARAMETERSPEC-NOBS-00, because SecretKeySpec.e1 read `generatedKey` from the new store
# and the KeyStore write went to the old one, so no `randomized` was staged onto the key's
# encoding. The key store half breaks no clause -- the key comes from a store of a type
# the rule admits -- but since task 5.10 the IV half does: `getEncoded()` ENSURES
# `preparedKeyMaterial` and IvParameterSpec REQUIRES `randomized[iv]`, two different
# predicates that the seed had conflated, so an IV built from key material draws
# IVPARAMETERSPEC-NOBS-00. Continuing the original note --
# the key comes from a key store of a type the rule
# admits, loaded, and the IV is that key's own encoding.
#
# On the harness grammar: a line without `-> x` dispatches the advices and does not perform
# the call, and a `bind` line performs the call and dispatches nothing. The load therefore
# appears twice -- once to really initialise the store, once for the monitor to see it --
# and setKeyEntry, which no pointcut names, is bound so the store really holds a key.
# Measured on this JVM: PKCS12 accepts a SecretKey through setKeyEntry and getKey returns a
# real javax.crypto.spec.SecretKeySpec; JKS refuses it ("Cannot store non-PrivateKeys") and
# BKS and AndroidKeyStore do not exist off Android.
bind kg = KeyGenerator.getInstance("AES")
bind sk = kg.generateKey()
KeyStore.getInstance("PKCS12") -> ks
bind ready = ks.load(null)
ks.load(null)
bind stored = ks.setKeyEntry("a2", sk, chars, null)
ks.getKey("a2", chars) -> key
key.getEncoded() -> enc
new IvParameterSpec(enc) -> iv
