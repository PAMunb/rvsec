# gh109 task 3.R, the consumer-chain shape of group G3 (task 3.3): a key spec built under
# observation, then a key derived from it.
#
# `PBEKeySpecSpec` writes `speccedKey` for the spec below, so the `gen` read
# (SecretKeyFactory.crysl:28) answers SATISFIED through `validateAny` -- at arity 1, because
# the clause leaves its second position anonymous -- nothing is drawn, and
# `generatedKey[key, algorithm]` (:31) is written for the returned key with the canonical
# algorithm, which is what `CipherSpec` and `MacSpec` read against.
#
# The spec conforms to the RULE and not merely to what the platform accepts, which is what
# makes the pair separate. `PBEKeySpec.crysl` asks for an iteration count of at least 10000
# and for a salt that was randomised under observation, so the salt is drawn by a SecureRandom
# this trace obtains and calls: a salt spelled `bytes(16)` inline clears `conforms` through
# PBEKEYSPEC-NOBS-01, `speccedKey` is never written, and the `gen` read below then answers
# NOT_OBSERVED for a reason that has nothing to do with what the pair is about.
#
# The separating trace is SecretKeyFactorySpec-unobserved-spec.txt, identical but for the
# `bind`, which draws SECRETKEYFACTORY-NOBS-00 and writes no key predicate at all.
SecureRandom.getInstance("SHA1PRNG") -> r
bind salt = bytes(16)
r.nextBytes(salt)
new PBEKeySpec(chars, salt, 100000, 256) -> spec
SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256") -> skf
skf.generateSecret(spec)
