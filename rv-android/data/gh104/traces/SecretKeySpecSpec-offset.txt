# the satisfying half of the c4->c2 fusion: the four-argument constructor with a
# length the rule's only CONSTRAINTS clause accepts. There is no violating half to
# write -- the constructor throws for every offset/length combination the clause
# rejects, so SECRETKEYSPEC-CONSTR-01 is unreachable at an `after ... returning`
# join point (data/gh105/evidence/f1-SecretKeySpecSpec-unreachable-constraint.md).
#
# It satisfies the CONSTRAINTS clause and not the REQUIRES one. Task 5.10 gave this
# overload the read the two-argument one always had, because api30 binds `keyMaterial`
# in both events of `Cons := c1 | c2` and states one REQUIRES over it; the material here
# comes from a SecureRandom, which `preparedKeyMaterial` is not, so SECRETKEYSPEC-NOBS-01
# fires. This is the one trace that measures the new site.
bind km = bytes(32)
SecureRandom.getInstance("SHA1PRNG") -> r
r.nextBytes(km)
new SecretKeySpec(km, 0, 32, "AES") -> spec
