# The chain this specification exists to carry, observed at both ends: a key built from
# randomised material hands its encoding to a consumer of `randomized`.
#
# api30 SecretKey ENSURES preparedKeyMaterial[keyMaterial] after ge (SecretKey.cryptsl:25),
# which the seed writes as `randomized` -- ledger clause #32, recorded at task 4.10 and
# undone at 5.10 with 6.1. Nothing here is a defect: the material comes from an observed
# SecureRandom, the key is constructed from it, and the IV is the key's own encoding.
#
# `getEncoded()` returns a fresh clone on every call, so no store keyed on the array can
# see the material through it: this event is the only thing that carries the predicate
# from the key to the bytes it returns. Measured before the edit -- with the read and the
# write on the old substrate and every reader of `randomized` already on the new one, the
# write had no reader at all and this conforming program drew IVPARAMETERSPEC-NOBS-00.
bind km = bytes(16)
SecureRandom.getInstance("SHA1PRNG") -> r
r.nextBytes(km)
new SecretKeySpec(km, "AES") -> k
k.getEncoded() -> enc
new IvParameterSpec(enc) -> iv
