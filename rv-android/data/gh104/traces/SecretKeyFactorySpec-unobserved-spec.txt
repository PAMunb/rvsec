# gh109 task 3.R, the separating half of the consumer chain: the key spec is built outside the
# monitored set, so `speccedKey` was never written for it and the read answers NOT_OBSERVED.
# The site draws SECRETKEYFACTORY-NOBS-00 and NOT SECRETKEYFACTORY-CONSTR-00 -- an absence of
# evidence is not evidence of a refused specification (INV-INS-143).
#
# The second half of what this trace shows is the write that does not happen: the `gen` body
# stages `generatedKey` only under `if (conforms)`, so a key derived from a spec nobody watched
# does not go on to carry the predicate `CipherSpec` will ask for. The silence propagates one
# step and stops being attributable there, which is the reason the conforming branch is
# guarded at all.
#
# Everything but the `bind` is the conforming trace's, salt included, so the one difference
# between the two is whether the constructor was observed. The salt is randomised here as
# well, and draws nothing: the constructor is bound, so `PBEKeySpecSpec` sees no `c1` at all
# and could not have been the cause of either verdict.
SecureRandom.getInstance("SHA1PRNG") -> r
bind salt = bytes(16)
r.nextBytes(salt)
bind spec = new PBEKeySpec(chars, salt, 100000, 256)
SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256") -> skf
skf.generateSecret(spec)
