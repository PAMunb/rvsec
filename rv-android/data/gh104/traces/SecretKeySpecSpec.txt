# An allow-listed algorithm over key material an observed SecureRandom filled. The label
# this trace carried -- legitimate -- was about the algorithm and the ordering, and it was
# written before the file read the clause api30 actually states. It reads it now:
# SecretKeySpec REQUIRES `preparedKeyMaterial[keyMaterial]`, ENSURED only by
# Key/SecretKey.getEncoded(), so randomised bytes do not satisfy it and this construction
# draws SECRETKEYSPEC-NOBS-00. The idiom the rule does admit is in
# SecretKeySpecSpec-prepared-material.txt (tasks 5.10 and 6.1).
bind km = bytes(32)
SecureRandom.getInstance("SHA1PRNG") -> r
r.nextBytes(km)
new SecretKeySpec(km, "AES") -> spec
