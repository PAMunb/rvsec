# The third producer of `generatedKey` reaching the consumer: KeyStore.getKey() into
# Cipher.init. api30 writes `generatedKey[key, _]` here (KeyStore.cryptsl:97) -- the second
# place is the oracle's anonymous variable -- and the store has no wildcard, so task 5.6 writes
# the key's own algorithm and records the departure (researcher decision, 2026-08-22).
#
# This trace is what makes the departure checkable. The key that comes out of the store reports
# "AES" and the Cipher's transformation splits to "AES", so the concrete value answers exactly
# where `_` would have, and a conforming program stays silent.
#
# Measured on Temurin 21, and the reason KeyStoreSpec must write at all: `getKey` returns a
# *fresh* key object, not the one `setKeyEntry` was given -- on PKCS12 a new
# javax.crypto.spec.SecretKeySpec over the same material -- so an identity-keyed store cannot
# carry a predicate through a key store, and the origin of what comes out is established here
# or nowhere. PKCS12 is the store type this composition needs: JKS refuses a SecretKey
# ("Cannot store non-PrivateKeys"), and BKS and AndroidKeyStore do not exist off Android.
bind kg = KeyGenerator.getInstance("AES")
bind sk = kg.generateKey()
KeyStore.getInstance("PKCS12") -> ks
bind ready = ks.load(null)
ks.load(null)
bind stored = ks.setKeyEntry("a2", sk, chars, null)
ks.getKey("a2", chars) -> key
Cipher.getInstance("AES/CBC/PKCS5Padding") -> c
c.init(1, key)
