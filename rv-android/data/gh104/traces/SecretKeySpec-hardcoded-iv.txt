# The violating side, and the control that decided the disposition of the read.
#
# The key material is hard-coded: SecretKeySpecSpec accuses it (SECRETKEYSPEC-NOBS-00),
# does not bind `spec`, so no `generatedKey` is ensured, so this event stages nothing and
# the encoding reaches IvParameterSpec with no observed randomised origin -- two reports,
# and both are about a real defect.
#
# What it pins is the option that was declined. api30 states its ENSURES with no REQUIRES
# section, so a literal translation would write `randomized` on every encoding
# unconditionally; measured, that turns this program's second report off and hands a
# hard-coded key's bytes to Cipher's IV as randomised. The read stays, guarding the write,
# because of this line.
bind km = bytes(16)
new SecretKeySpec(km, "AES") -> k
k.getEncoded() -> enc
new IvParameterSpec(enc) -> iv
