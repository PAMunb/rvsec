## What a NOBS line is
The campaign ran Android apps instrumented with runtime monitors generated from JavaMOP `.mop` specs (set `jca_android`). A spec event reads a CrySL-style REQUIRES predicate via `PredicateStore.instance().validate(Property, object, ...)` and gets one of SATISFIED / VIOLATED / NOT_OBSERVED. `NOT_OBSERVED` (code `...-NOBS-nn`) means: the object is `null`, or no producer event ever recorded (`ensure`) that property for **that exact object identity** (`System.identityHashCode`). So a copy of an array, a new array wrapping the same element, bytes read from storage, or an object created inside the framework arrives without a predicate no matter how correct its origin.
- Runtime store: `/pedro/desenvolvimento/workspaces/workspaces-doutorado/workspace-rv/rvsec/rvsec/rvsec-core/src/main/java/br/unb/cic/mop/PredicateStore.java` (validate ~:342-362; identity lookup ~:162-213).
- Specs (exactly what ran): `/pedro/desenvolvimento/workspaces/workspaces-doutorado/workspace-rv/rvsec/rvsec/rvsec-mop/src/main/resources/jca_android/*.mop`, with `codes.csv` mapping each code to its spec file:line and event. READ THE .MOP for each code you judge: which event fires it, what property it reads, on which object, and which other events (in which .mop files, grep `ensure`) produce that property and under which guards.
