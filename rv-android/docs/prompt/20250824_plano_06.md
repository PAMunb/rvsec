## **Implementation Notice**

The existing template system already works well. No need for complex template caching, dynamic selection, or performance optimization. The current template inheritance with `extends` is sufficient.

## **Simple Template Extensions**

### **Basic Template Inheritance (Existing System)**
```xml
<!-- mop_vision.xml -->
<template name="mop_vision" extends="vision.xml">
    <variables>
        <!-- Add coverage variables when needed -->
        <variable name="coverage_enabled" type="bool" required="false" default="false"/>
        <variable name="ui_coverage_tracker" type="UICoverageTracker" required="false"/>
    </variables>
    
    <section name="context_base">
        <!-- Use existing fragments -->
        {% include "ui_elements" %}
        {% include "monitored_operations" %}
        {% include "history_fragment" %}
        {% include "screenshot_fragment" %}
        
        <!-- Add coverage guidance if enabled -->
        {% if coverage_enabled %}
        {% include "coverage_guidance" %}
        {% endif %}
    </section>
    
    <section name="instructions_base">
        {% include "vision_instructions" %}
    </section>
</template>
```

### **Simple Coverage Fragment**
```xml
<!-- coverage_guidance.xml -->
<template name="coverage_guidance">
    <content>
## Coverage Guidance

**Element Coverage**: Focus on [UNTESTED] elements when available
**Action Balance**: Vary between click, text input, and coordinate actions
**MOP Priority**: Prioritize [M] and [DM] elements for violation discovery
    </content>
</template>
```

## **Integration with Existing System**

### **Use Existing RVAndroidPromptFramework**

The existing system already provides:
- Fragment registration (`RVAndroidPromptFramework._register_fragments()`)
- Template inheritance (`extends` attribute)
- Strategy registration via `LLMComponentFactory`
- Information manager coordination

## **Why Existing System is Sufficient**

### **Current Template Engine Already Provides:**
- Template inheritance via `extends` attribute
- Fragment inclusion via `{% include "fragment_name" %}`
- Variable passing and conditional rendering
- Jinja2 templating with full functionality

### **Current Strategy Registration Already Provides:**
- Strategy registration via `LLMComponentFactory.register_strategy()`
- Fragment registration via `RVAndroidPromptFramework._register_fragments()`
- Template path registration via `template_repository.register_template_directory()`

### **No Need for Complex Features:**
- **Template Caching**: Templates render fast enough without caching
- **Dynamic Template Selection**: Simple strategy-to-template mapping is sufficient
- **Performance Optimization**: No performance problems to solve
- **Complex Configuration Management**: Simple JSON loading works fine

---

## **Simple Implementation Summary**

1. **Add new template files** (mop_vision.xml) to existing template directory
2. **Register new strategies** using existing `LLMComponentFactory.register_strategy()`  
3. **Add coverage fragment** to existing fragment registration
4. **Use existing template inheritance** with `extends` attribute
5. **No complex template engine modifications** needed

The existing system provides all necessary functionality without over-engineering.
