- **Better MOP targeting** through [DM] priority guidance
- **Systematic UI coverage** with element tracking and annotations
- **Balanced testing** by encouraging action type variety
- **Maintainable system** with ~3,000 total lines vs ~9,000 over-engineered lines

## **Simple Implementation Summary**

### **What Was Simplified:**

1. **Configuration Management (Plano_07)**: Removed hierarchical variants, A/B testing → Simple JSON loading
2. **Template System (Plano_06)**: Removed caching, dynamic selection → Use existing template inheritance  
3. **Context Intelligence (Plano_02)**: Removed complex pattern analysis → Simple M/DM counting
4. **UI Coverage (Plano_03)**: Balanced analytics for LLM decisions, removed over-engineering
5. **Performance (Plano_08)**: Use existing PerformanceMonitor, no custom validation framework

### **What Remains Essential:**

1. **UICoverageTracker**: Element tracking with [UNTESTED]/[TESTED-Nx] annotations (tracks LLM selections)
2. **System Coverage Events**: ActionService subscribes to COVERAGE_UPDATED/MOP_ERROR_DETECTED from rv-coverage (tracks APK execution)  
3. **Action Balance**: Track action types to prevent click-only bias
4. **MOPVisionStrategy**: Extends VisionStrategy with basic M/DM priority guidance  
5. **Coverage Fragment**: Simple guidance for LLM prompts
6. **Integration**: Works with existing template, fragment, and strategy systems

### **Important Distinction - Two Coverage Systems:**
- **System Coverage (rv-coverage)**: Monitors method execution in instrumented APK via logcat → Events: COVERAGE_UPDATED, MOP_ERROR_DETECTED
- **UI Coverage (UICoverageTracker)**: Tracks which UI elements LLM has selected → Purpose: Systematic testing with annotations

### **Total Complexity Reduction:**
- **Before**: ~9,000 lines of over-engineered code
- **After**: ~3,000 lines of essential, maintainable functionality
- **Maintained**: All features necessary for effective LLM-guided testing

## **Implementation Approach**

### **Simple Integration Strategy**
1. **UICoverageTracker**: Standalone component with minimal dependencies
2. **MOPVisionStrategy**: Extends existing VisionStrategy 
3. **Coverage Fragment**: Integrates with existing fragment system
4. **Templates**: Use existing template inheritance (`extends` attribute)
5. **Configuration**: Simple JSON loading without complex management

### **No Circular Dependencies**
- All components use existing system infrastructure  
- MOPVisionStrategy simply extends VisionStrategy
- UICoverageTracker works independently  
- Templates use standard Jinja2 inheritance
