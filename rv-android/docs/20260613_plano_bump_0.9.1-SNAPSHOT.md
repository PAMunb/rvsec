# Plano — Bump de versão 0.9.0 → 0.9.1-SNAPSHOT

Data: 2026-06-13
Branch: `modules`

## Objetivo

Subir a versão do projeto de `0.9.0-SNAPSHOT` → **`0.9.1-SNAPSHOT`** (Maven, com sufixo
`-SNAPSHOT`) e as tags de imagens Docker `0.9.0` → **`0.9.1`** (forma release, sem
`-SNAPSHOT`, mantendo a convenção atual), além dos scripts de runtime/build ativos.

**Princípio orientador (decisão do usuário): NÃO mexer nos históricos.** Artefatos de
experimentos passados, relatórios, OpenSpec archives, docs e reatores Maven com versão
própria divergente permanecem na tag/versão antiga.

## Sequência de execução

**Fase 0 — Higiene de git.** A árvore já tem mudanças não commitadas (`.project`, jars, etc.).
O commit do bump deve ser **escopado apenas aos arquivos do bump** (não varrer o resto).

**Fase 1 — Maven (reator).** Da raiz:
```bash
mvn versions:set -DnewVersion=0.9.1-SNAPSHOT -DgenerateBackupPoms=true
```
Validar com `git diff --stat` que **só** os 48 POMs do reator mudaram (zero alterações em
crylogger / rv-monitor docs+installer / docker-mop / teste-sootup / gesda / reachability).

**Fase 2 — rv-android POM (órfão ativo).** Bump explícito do `rv-android/pom.xml`
(`<version>` e `<parent><version>` → `0.9.1-SNAPSHOT`).

> `rvsec-gesda` e `rvsec-reachability` **não** estão em `<modules>` de `rvsec-android/pom.xml`
> (que lista só `rvsec-apk`, `rvsec-logger-logcat`, `rvsec-gator`, `rvsmart`,
> `rvsec-frame-computer`, `rvsec-instrumentation-dexlib2`). Como `versions:set` só percorre os
> POMs declarados no reator, ele **nunca abre** esses dois arquivos — **nem a versão própria
> nem o `<parent>` deles mudam**. Ficam 100% intactos em `0.9.0-SNAPSHOT`. Nenhuma ação.

**Fase 3 — Scripts runtime.** `configure.sh`, `rvsec/config.sh`, `run_phase5_validators.sh`.

**Fase 4 — Docker.** Build scripts + Dockerfile FROM + run helpers + compose canônico +
defaults Python.

**Fase 5 — Testes.** Atualizar asserts de nome de jar nos 2 arquivos de teste.

**Fase 6 — Verificação.**
- `git grep -n "0.9.0-SNAPSHOT"` e `git grep -n "rvandroid:0.9.0"` → confirmar que só restam
  ocorrências históricas/intencionais (gesda, reachability, experimentos, docs).
- `mvn versions:commit` (remover `*.versionsBackup`).
- Build de sanidade: `mvn -q -DskipTests install` (ou ao menos `validate`) no reator para
  provar que a resolução de parents/deps não quebrou.

**Fase 7 — Commit.** Mensagem escopada, ex.:
`chore(release): bump 0.9.0-SNAPSHOT -> 0.9.1-SNAPSHOT (poms reator + rv-android + scripts/docker ativos)`.

## Riscos

- **gesda/reachability:** intocados (não estão em `<modules>` do parent). Seu `<parent>`
  continua referenciando `rvsec-android:0.9.0-SNAPSHOT`, que deixará de ser produzido pelo
  build novo. Só importaria se fossem buildados isoladamente — não são. Sem ação, por decisão
  do usuário.
- **Imagens Docker `0.9.1` precisam ser efetivamente reconstruídas/publicadas** para os
  compose/scripts atualizados funcionarem (caso contrário pull falha). Bump de tag ≠ build.
- **Testes Python** falharão até atualizar os asserts (Fase 5).
