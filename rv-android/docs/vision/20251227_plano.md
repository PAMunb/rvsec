### 2.2 Licao Aprendida: Parser Completo

**ERRO COMETIDO**: Inicialmente simplificamos o parser, perdendo conhecimento critico.

**CORRECAO**: Restauramos `tool_call_parser.py` do backup com TODOS os fixes:

| Pattern | Descricao | Exemplo |
|---------|-----------|---------|
| 0 | Missing leading zero | `.91` -> `0.91` |
| 0b | Double colon | `"x":": 541` -> `"x": 541` |
| 0c | Trailing quote | `"y": 473"` -> `"y": 473` |
| 0d | Two numbers | `"x": 867 335` -> `"x": 867` |
| 1 | Missing y key | `"x": 352, 782` -> `"x": 352, "y": 782` |
| 2 | Array format | `"x": [352, 782]` -> `"x": 352, "y": 782` |
| 3 | Malformed array | `"x": [499", "499"]` -> correto |
| 4 | Equals sign | `"x": = 100` -> `"x": 100` |
| 5 | Truncated JSON | Adiciona `}` faltantes |

**Funcao `normalize_tool_args`** trata:
- `{"x": [499, 510]}` -> `{"x": 499, "y": 510}` (Qwen array)
- `{"coordinate": [464, 487]}` -> `{"x": 464, "y": 487}` (Fara-7B)
- `{"x": "681"}` -> `{"x": 681}` (string para int)
