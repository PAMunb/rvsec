### 2.3 Investigacao Fara-7B (CONCLUIDA)

Ver detalhes em: `docs/013_prompt_and_parser_fixes.md`

**Problema identificado:** Fara-7B retornava IDs de elementos ao inves de coordenadas:
```json
// Esperado
{"name": "android_click", "arguments": {"x": 540, "y": 1056}}
// Retornado
{"name": "android_click", "arguments": {"id": "ImageView 'Search'"}}
```

**Solucao aplicada:**
1. SYSTEM_PROMPT_VISUAL atualizado com instrucoes explicitas para coordenadas pixel
2. Tool definitions atualizadas com ranges (0-1080, 0-1920)
3. Parser com suporte a multiplos nomes de tool (android_click, u2009, tap, click)

**Resultados apos correcoes (validacao rapida):**
| Metrica | Antes | Depois |
|---------|-------|--------|
| Hit Rate | 23.5% | 31.8% |
| Coord Rate | 68.2% | 86.4% |

### 3.2 MiniCPM-V-4_5 (NAO FUNCIONA)

**Status**: Testado mas NAO funciona com prompt padrao do evaluator.

**Configuracao testada:**
- Servidor: vLLM com bitsandbytes quantization
- Modelo: openbmb/MiniCPM-V-4_5 (8.7B params)
- Temperatura: 0.5 (necessario para evitar modo "thinking")

**Problemas encontrados:**
1. Com temp=0.01: modelo entra em modo "thinking" (`<think>` repetido)
2. Com temp=0.5: 100% "No tool calls found" no teste completo
3. Teste manual com prompt customizado funcionou (100% hit rate)

**Conclusao**: MiniCPM-V precisa de prompt customizado para funcionar. O prompt padrao do evaluator nao eh adequado para este modelo.

**Fixes aplicados (para referencia futura):**
- Parser: Pattern 0d para `"x": 867 335` (dois numeros com espaco)
- Coordenadas: MiniCPM-V usa [0, 1000) normalizado como Qwen3-VL
