# CLAUDE.md - rv-static-analysis

Guidance for Claude Code working in the rv-static-analysis module. See `rv-android/CLAUDE.md` for workspace-wide setup (uv sync, pytest, env vars, spec sets).

## Purpose
Runs unified GATOR static analysis on APKs and parses the single JSON output into `StaticAnalysisData` domain objects (reachability, windows, transitions, components). Feeds navigation guidance and MOP prioritization in rv-agent, and the coverage denominator in rv-coverage.

- `StaticAnalyzer` (`analysis/static/static_analysis.py`) — orchestrates one GATOR invocation, produces `StaticAnalysisData`.
- `RVStaticAnalysisConfig` (`config.py`) — Pydantic config.
- Parser (`parser/static/static_analysis_parser.py`) — `parse_file()` / `StaticAnalysisParser`.
- `check_denominator` (`analysis/static/denominator_gate.py`) — refuses a coverage denominator that cannot be right, before the run publishes a percentage.

Authoritative JSON contract (schema + field semantics) lives with the producer: `rvsec/rvsec-android/rvsec-gator/CLAUDE.md` and `rv-android/openspec/specs/analysis/spec.md`. Section invariants (priority ordering, graceful degradation) are specified in `analysis/spec.md` — do not restate them here.

## Config resolution
Priority: (1) explicit params → (2) `rvsec_root` standard layout → (3) `RVSEC_HOME` → (4) cwd parent.
Key fields: `rvsec_root`, `lib_dir`, `gator_dir`, `analysis_client_jar`, `android_jar`, `mop_dir`, `output_dir`, `jvm_memory` (default `8g`), `cg_algorithm` (`spark|cha|rta|vta`, default `spark`), `skip_wtg` (default `False`).
`get_tool_command()` builds the GATOR command; standard layout expects `rv-android/lib/gator/{gator,rvsec-analysis-client.jar}` and `rvsec/rvsec-mop/src/main/resources/jca/`. Besides `-clientParam codePackage=<key>` it emits `-clientParam codePackageSource=<manifest|manifest-neutralized|detector>`: the origin lives only on the Python side (`App.code_package_source`) and the run writes it to a log that never reaches disk, so without a channel of its own the artefact cannot record which policy produced the key it was filtered by (INV-ANA-66).

**`sys.executable` launcher:** `get_tool_command()` invokes the GATOR launcher with `sys.executable`, not literal `"python"` — avoids failures on systems without `/usr/bin/python` (clean Debian/Ubuntu, containers lacking `python-is-python3`).

## Parser semantics
Parses four sections — `reachability`, `windows`, `transitions`, `components` — each independently via order-independent key lookup, plus a trailing `complete` flag (incomplete/truncated samples set it `False`). A missing/corrupt section (e.g. timeout killed GATOR mid-write) yields empty domain objects rather than a failure. The authoritative on-disk write order lives with the producer (`rvsec/rvsec-android/rvsec-gator/CLAUDE.md`).

- **The artefact carries its own scope — parsing takes no package key (gh102).** GATOR was invoked with `-clientParam codePackage=<key>` and dropped everything outside that key before writing, so `reachability` *is* the application's whole method universe: every entry is loaded, unfiltered, and that set is the coverage denominator (INV-ANA-59). `windows`, by contrast, is **not** scoped by the producer — framework and library activities (`androidx.activity.ComponentActivity`, `com.canhub.cropper.CropImageActivity`) appear there and would inflate the activity denominator — so an `ACTIVITY` window is admitted exactly when its class is present in `reachability` (INV-ANA-60), a test the artefact answers on its own and therefore cannot disagree with the producer. `DIALOG`, `OPTIONSMENU` and other types are admitted unconditionally, because they can be system-provided overlays triggered by app code. No consumption-path function accepts a key (INV-ANA-61): the signatures are `parse_file(path)` and `read_static_analysis_files(results_dir, apk)`. Re-asking the scoping question here could only contradict the producer, and on an app built with `applicationIdSuffix` it emptied the universe outright.
- **Choosing the scope is a production-path concern.** `RVStaticAnalysisConfig.get_tool_command(code_package=…)` emits the `-clientParam`, and `analyze()` records `code_package` / `code_package_source` on its own `StaticAnalysisResult`. The key is the applicationId the APK declares unless the run enabled `PackageDetector` (`--package-detector` / `RV_PACKAGE_DETECTOR`), which elects the implementation package instead — what a corpus of Godot games needs (manifest `ir.hsn6.trans`, classes under `org.godotengine.godot`). It is never recovered from a stored JSON: GATOR writes the manifest package into the artefact's `package` member whatever key filtered it, so the run must record its own key (INV-ANA-58).
- **The artefact records its own scope, and the parser reads it back verbatim (INV-ANA-66).** Three members ride beside the manifest `package`: `codePackage` (the key GATOR actually filtered by), `codePackageSource` (`manifest`, `manifest-neutralized` or `detector`) and `class_defs_under_key` (the compiled classes under that key that survive `RvsecAnalysisClient.isAppClass`, counted at write time — a **net** count, never the raw one). `parse_file()` surfaces them as `StaticAnalysisData.code_package` / `.code_package_source` / `.class_defs_under_key`. The producer writes `""` for an unrecorded string and `-1` for an unrecorded count; both become `None`, so *not recorded* stays distinguishable from an empty key or a genuinely zero universe — the state of all 162 artefacts written before the key reached disk. Reading a recorded key is not resolving one, so INV-ANA-61 stands: nothing here filters.
- **Nothing is transformed on the way in (INV-ANA-67).** Class names, window names and signatures are stored exactly as the artefact spells them. The parser used to rewrite a dot to a `$` whenever both sides were capitalized, which is always wrong on GATOR output — `SootClass.getName()` writes the JVM binary name, so such a dot is a package boundary — and it was applied to one side of an equality test whose other side is the raw logcat. Measured: 465 classes across 7 of the 162 corpus artefacts, with `com.hwloc.lstopo.ZoomView.ZoomView` publishing 0.00% against 1080 events that named it correctly.
- **The chain carries two granularities, and they are different rulers on purpose.**
  A **target** is seeded by class + method name with **no parameters** (`MatchPolicy.LENIENT`,
  INV-ANA-35), so every overload of a targeted method becomes a seed and `reachesTarget` answers a
  deliberately coarse question. **Coverage** is matched by the **complete Soot signature**:
  `repository_initializer` keys `MethodCoverageData` on `method.signature`, and the crossing tests
  the raw `RVSEC-COV` payload against that key by literal equality. So the denominator *does* index
  by signature and the crossing *does* test by signature — the bullet below is about how targets are
  seeded, not about how coverage is measured, and reading it as the latter would build a denominator
  measurably smaller than the code's. The join key that binds static analysis, coverage and
  violations into one row is the coarse one, `(apk, class, method, spec)`, because the runtime side
  cannot supply more: a violation is located from a `StackTraceElement`, which carries no parameter
  descriptor. Coarse where the runtime forces it, fine where the artefact allows it.

- **Method granularity is `(class, method)`. Overloads are not distinguished anywhere, and no analysis should assume they are.** GATOR seeds reachability from MOP targets under `MatchPolicy.LENIENT`, which matches on class name + method name only and ignores parameter types entirely (`TargetResolver.resolveInScene`); every overload of a targeted method becomes a seed. The runtime side agrees by construction — `rv-monitor` locates a violation from a `StackTraceElement` (`Class.method(File:line)`), which carries no parameter descriptor, and `rvsec-core` parses it back into `(class, method, loc)`. So the `(apk, class, method, spec)` key that joins static analysis, coverage and violations is method-name-granular at both ends. Do not build a comparison, a gate or a denominator that keys on a full signature: it cannot be honoured end to end, which is why the pipeline never tries.
- **`Loaded N MOP signatures` in the GATOR log is not a target count.** N counts signature-distinct rows, so it is inflated by overloads: `jca` prints **120** while seeding **68** distinct `(class, method)` targets; `jca_android` prints **207** and seeds **113**. Use it to confirm *which spec set* was loaded, never to detect *whether the target set changed* — collapse to distinct `(class, method)` for that. The `jca_android` pair is the one that moves: the set went from 23 to 48 `.mop` files with gh105/gh109, and the figures this bullet carried before (119/67) were the pre-gh105 ones, wrong by 74%. A ruler that offers itself for set identification and names the wrong set is worse than no ruler, so re-measure it whenever the set changes — `tests/parity/test_gh111_specset_ruler.py` pins the file counts, which is the half that moves for free.

## Denominator gate (INV-ANA-69)
`check_denominator(classes, compiled_under_key, key)` in `analysis/static/denominator_gate.py` is a pure predicate over the artefact — it divides and nothing more, because `class_defs_under_key` arrives already filtered by the same `isAppClass` that filtered the parsed side. One predicate on both terms is what makes the ratio comparable; the gate holds a count and not the names, so it cannot perform a subtraction of its own. It raises `DenominatorImplausibleError` on three distinct conditions, in this order:

1. **zero compiled universe** (`class_defs_under_key == 0`) — first, and not merely to dodge `ZeroDivisionError`: `0/0` is not a low ratio, it is no ratio, and it is the signature of a key that matches nothing compiled (the state of 75 of the 162 corpus APKs under the literal manifest key);
2. **empty parsed side** (`reachability` holds no entry);
3. **degenerate ratio** (`parsed / compiled_under_key < MIN_PARSED_RATIO`, `0.15`).

`StaticAnalyzer.analyze()` wires it through `_check_denominator()` — the only place holding both the APK and the key, which is why the gate lives there and the parser stays keyless. It costs one parse that did not exist before (`analyze()` never read the artefact; `get_static_data()` did). A refusal fails **that APK's** result (`success=False`, message appended to `errors`) instead of propagating: the `ErrorHandler` decorator would swallow a raise and return `None`, which is exactly the silence the gate exists to end, and stopping a 200-APK campaign for one artefact is not warranted. An artefact recording no `class_defs_under_key` is not judged at all — there is no universe to divide by, and inventing one would be the silent measurement the gate removes.

**A refusal moves the artefact aside, and that is what makes the gate a gate.** Nothing downstream reads the result object: `pre_processor._report_missing_static_analysis` builds its list with `os.path.exists(<apk>.apk.json)` and `result_processor._resolve_static_data` locates the file by name. Left in place, a refused artefact is re-parsed and its collapsed class list published as a percentage with `measured=true` — the outcome INV-ANA-69's own scenario forbids. So `_quarantine_refused_artifact()` renames it to `<apk>.apk.json.refused`: the consumers see it as absent and the row takes the honest path that already exists (empty coverage cells, `measured=false` per INV-PLT-35, violation columns written as usual). Renamed and not deleted, because the refusal is a tripwire on a stale `lib/gator/` jar or an unresolved key, and both are diagnosed from the artefact's own recorded key, origin and `class_defs_under_key`.

**Threshold provenance.** Calibrated over the 162-APK corpus: with both terms answering to one predicate, the 158 healthy artefacts sit at exactly 1.0 and the four collapsed ones between 0.0010 and 0.0393. `0.15` sits 3.8x above the collapsed ceiling and 6.7x below the healthy floor, inside a 25x separation. Once the producer-side guard resolves the same key as the client, the degenerate branch is a tripwire on a stale `lib/gator/` jar (client filtering by the new key, guard still running the old) and on any regression of INV-ANA-65 — not a discriminator over healthy apps.

## Cache reuse is keyed (INV-ANA-70)
`_execute_command()` does not treat existence alone as a hit. `_disagreeing_recorded_key()` parses the stored artefact and returns the key it records when that key is not this run's; on a disagreement the file is removed and the analysis re-runs, with a warning naming both keys. `None` — *reuse it* — deliberately covers two cases: an artefact recording **no** key (all 162 of the article corpus, produced before INV-ANA-66) and one recording this run's own key. An unreadable artefact is reused too, because the parser recovers truncated JSON on purpose (INV-ANA-06), so a parse failure here says something about the check, not about the file. Without this, a run whose key policy changed would reuse the old artefact and the denominator gate would then judge it by the new key.

`--force` is the *deliberate* invalidation, for a fresh artefact under the same key: `_discard_cached_artifact()` removes `analyzer.analysis_file` before `analyze()` runs. It is declared on both subparsers and honoured by both.

## CLI flags
- `--cg-algorithm` (default `spark`) — call-graph algorithm.
- `--analysis-timeout <s>` (gh55) — per-APK GATOR timeout; **required for standalone runs** (see caveat).
- `--skip-wtg` (gh57) — appends `-clientParam skipWtg=true`; GATOR emits reachability + `windows[]` and returns without building the WTG (`transitions[]` empty). For known-slow APKs where WTG construction is guaranteed to time out.
- `--package-detector` / `--no-package-detector` (gh98) — which package scopes app-owned classes. Default: the declared applicationId, passed to GATOR as `-clientParam codePackage=` verbatim. Honors `RV_PACKAGE_DETECTOR` under flag > env > default; an unparseable value exits nonzero before any APK is opened.
- `--strip-build-type-suffix` / `--no-strip-build-type-suffix` (gh111) — neutralize the Gradle build-type suffix of the declared applicationId before using it as the scope key: `com.example.app.debug` becomes `com.example.app`. Default off; honors `RV_STRIP_BUILD_TYPE_SUFFIX` under flag > env > default. The suffix renames the application, not the code, so under the declared id nothing was ever compiled — 75 of the 162 article-corpus APKs are in that state. The denylist is not total, and a key it cannot resolve is caught by the denominator gate rather than silently published. When `--package-detector` is also on the detector wins, and the origin recorded is `detector`, never `manifest-neutralized` (INV-CORE-18).
- `--force` — removes the stored `<apk>.apk.json` before analyzing, so the run regenerates it under the same key. Distinct from the automatic regeneration of INV-ANA-70, which fires only when the key *changed*.

### Standalone env-var caveat (gh55)
`__main__` is argparse-based, not Click, so it does **not** honor `RV_SA_TIMEOUT` / `RV_JVM_MEMORY` when run directly (`uv run rv-static-analysis ...`). Those env vars only bridge through rv-experiment (gh55 §9 Click `envvar=`). For standalone runs use `--analysis-timeout` (added precisely to close this gap). Architectural fix tracked in `openspec/changes/gh-tbd-env-vars-architecture/`.

`RV_PACKAGE_DETECTOR` and `RV_STRIP_BUILD_TYPE_SUFFIX` are the exceptions, and deliberately so (gh98 D4): this command resolves both itself, because a standalone invocation is a run rather than a step inside one, and an operator who exported the variable in a shell or a container should get the same behaviour whichever command they invoke. They are read through the `ENV_PACKAGE_DETECTOR` / `ENV_STRIP_BUILD_TYPE_SUFFIX` constants and parsed by `resolve_bool_setting`, the same helper `rv-experiment` uses, so the two CLIs cannot drift on what a given string means. Both resolve in `main()` before any APK is opened, so an unparseable value exits nonzero immediately.

## Integration seams
- **rv-android-core:** `App`, `StaticAnalysisData`/`Classes`/`Windows`/`WindowTransitionGraph`/`Components`, `EXTENSION_STATIC_ANALYSIS`, base analyzer/error/logging infra.
- **rv-experiment:** `PreProcessor` calls `analyze()` in pre-processing, where `app.code_package` is the production key.
- **rv-platform:** runs no analysis — it only re-loads stored artefacts. `StaticAnalysisComponent` and `ResultProcessor` both call `read_static_analysis_files(results_dir, apk)`, passing no key.
- **rv-agent:** WTG → `TransitionManager`/`NavigationGuidance`; MOP flags → `RVAgentVisitor` action prioritization.
- **rv-coverage:** `Classes.methods` is the coverage denominator; `reachable` flag splits reachable vs unreachable.

## Error handling
- `StaticAnalysisException` — execution failures, **including the defensive post-condition** raised when GATOR returns but no output JSON exists at the expected path (catches a swallowed `CommandNotFoundError` / unreachable launcher, preventing silent zero-coverage downstream).
- `DenominatorImplausibleError` — the denominator gate refused the artefact (empty, degenerate, or no compiled universe under the key). Defined in `denominator_gate.py` rather than in `static_analysis.py`, which imports it: the reverse import would close a cycle. `analyze()` catches it and returns a failed `StaticAnalysisResult` naming the parsed count, the compiled count and the key, so the operator can re-run that APK once the jar or the key is corrected.
- `ConfigurationError` — invalid config.
- Parser returns empty sections for missing/malformed data; timeout produces partial JSON that the parser recovers.
