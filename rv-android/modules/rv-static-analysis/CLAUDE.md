# CLAUDE.md - rv-static-analysis

Guidance for Claude Code working in the rv-static-analysis module. See `rv-android/CLAUDE.md` for workspace-wide setup (uv sync, pytest, env vars, spec sets).

## Purpose
Runs unified GATOR static analysis on APKs and parses the single JSON output into `StaticAnalysisData` domain objects (reachability, windows, transitions, components). Feeds navigation guidance and MOP prioritization in rv-agent, and the coverage denominator in rv-coverage.

Paths relative to `src/rv_static_analysis/`.
- `StaticAnalyzer` (`analysis/static/static_analysis.py`) — orchestrates one GATOR invocation per APK, writes `<output_dir>/<apk>.apk.json`, returns a `StaticAnalysisResult` (`success`, `timed_out`, `errors`, `code_package`, `code_package_source`, `execution_times`).
- `RVStaticAnalysisConfig` (`config.py`) — Pydantic config; `get_tool_command()` builds the GATOR argv.
- Parser (`parser/static/static_analysis_parser.py`) — module-level `parse_file(path)` / `read_static_analysis_files(results_dir, apk)`, class `StaticAnalysisParser`.
- `check_denominator` (`analysis/static/denominator_gate.py`) — refuses a coverage denominator that cannot be right, before the run publishes a percentage.
- `compact_document` (`compact.py`) — offline conversion of a full-mode document into the compact document GATOR writes by default (`rv-static-analysis compact`).
- CLI (`__main__.py`) — argparse, subcommands `analyze`, `batch`, `compact`.

Authoritative JSON contract (schema + field semantics) lives with the producer: `rvsec/rvsec-android/rvsec-gator/CLAUDE.md` and `rv-android/openspec/specs/analysis/spec.md`. Section invariants (priority ordering, graceful degradation) are specified in `analysis/spec.md` — do not restate them here.

## Config resolution
Priority: (1) explicit params → (2) `rvsec_root` standard layout → (3) `RVSEC_HOME` → (4) cwd parent.
Key fields: `rvsec_root`, `lib_dir`, `gator_dir`, `analysis_client_jar`, `android_jar`, `mop_dir` / `targets_file` (exactly one, INV-ANA-33), `output_dir`, `jvm_memory` (default `12g`), `analysis_timeout` (default `600` s), `cg_algorithm` (`spark|cha|rta|vta`, default `spark`), `skip_wtg` (default `False`), `full_output` (default `False`; when `True` the command carries `-clientParam fullOutput=true`, and otherwise nothing for the mode, because compact is GATOR's default — INV-ANA-86), `cg_delegation` / `succ_depth` (default `None` = GATOR's own default; `succ_depth` has no CLI flag), `validate_on_init` (default `True`).
Standard layout under the root: `lib_dir = rv-android/lib`, `gator_dir = lib/gator` (`gator` launcher + `rvsec-analysis-client.jar`), `mop_dir = rvsec/rvsec-mop/src/main/resources/jca/` (only when no `targets_file`), `output_dir = out/`; `android_jar` is the first of `android-{33,29,28,27,26}/android.jar` under `$ANDROID_HOME/platforms`.

**Standalone runs default to the frozen `jca` set.** `rv-experiment` passes `mop_dir` = the run's specification set (`ExperimentConfig.resolve_spec_set_dir`); a direct `rv-static-analysis analyze` without `--mop-dir` seeds targets from `jca`.

`get_tool_command()` emits, besides `-clientParam codePackage=<key>`, `-clientParam codePackageSource=<manifest|manifest-neutralized|detector>`: the origin lives only on the Python side (`App.code_package_source`) and the run writes it to a log that never reaches disk, so without a channel of its own the artefact cannot record which policy produced the key it was filtered by (INV-ANA-66).

**`sys.executable` launcher:** `get_tool_command()` invokes the GATOR launcher with `sys.executable`, not literal `"python"` — avoids failures on systems without `/usr/bin/python` (clean Debian/Ubuntu, containers lacking `python-is-python3`).

**Timeout is a partial success.** `_execute_command()` catches `RVCommandTimeoutError`, sets `timed_out=True` and returns success: GATOR writes reachability first and flushes between sections, so the truncated document still carries the coverage-critical data.

## Parser semantics
Parses four sections — `reachability`, `windows`, `transitions`, `components` — each independently via order-independent key lookup, plus a trailing `complete` flag (incomplete/truncated samples set it `False`). A missing/corrupt section (e.g. timeout killed GATOR mid-write) yields empty domain objects rather than a failure. The authoritative on-disk write order lives with the producer (`rvsec/rvsec-android/rvsec-gator/CLAUDE.md`).

- **The document is read in streaming, without its distance members (INV-ANA-80).** `_load_json()` calls `rv_android_core.util.analysis_document.read_analysis_document(path, PairPolicy.DROP)`: one pass of `ijson` events (C backend `yajl2_c`) that builds every member as `json.loads` would, except `distanceTargets` and every `reachability[].methods[].targetDistances`, whose events are consumed without building anything. Those pairs can make a full-mode document hundreds of times larger, loaded whole it needs several times its size in memory, and no section parser reads them. The file's text is never held in memory. An empty file, a non-JSON file, a non-object root or an unopenable file is logged and yields the empty model.
- **Both output modes parse to the same model, and the parser is not told which it reads (INV-ANA-89).** GATOR writes the compact document by default (no whitespace, `targetDistances` reduced to the pairs at `d ≤ 3` plus the 3 nearest, top-level marker `distancePairs: {weighedMax: 3, k: 3}`) and the full one under `--full-output`; the producer-side contract is in `rvsec-gator/CLAUDE.md`. The two differ only in whitespace, in the marker and in which pairs they carry; the read drops the pairs and no section parser reads the marker, so `StaticAnalysisData` is equal and every metric is too. The marker keys are declared in `_JK` (INV-ANA-32), and the parsed copy keeps `distancePairs` like any other top-level member.
- **Truncation rule (INV-ANA-81).** A document cut by a producer killed mid-write keeps every top-level member whose value was read in full; the member in progress and everything after it are dropped, wherever the cut falls (inside a nested `events`, `widgets` or `intentFilters` list included). `complete` is `True` only when the `complete` member itself was read. The handling lives behind `_recover_truncated_json()`, which logs a warning naming the file and an info line with the number of members kept.
- **Parsed copy `<apk>.static.json` (INV-ANA-82..84).** `read_static_analysis_files(results_dir, apk)` digests the source (`digest_of_file`, chunked SHA-256) and, when `<apk>.static.json` beside it loads as an object whose `source.digest` equals that digest, builds the model from the copy. Any other state — absent, unreadable, unparseable, another digest — is a miss: the source is streamed and, unless the read was truncated, the copy is written (`json.dump` with compact separators to a `tempfile.mkstemp` in the same directory, then `os.replace`). The copy is the streamed dict plus a top-level `source: {digest, generator: "rv-static-analysis/1"}`; the section parsers never read `source`, so the copy parses to the same model as its source. Why: one document is read once per task of its APK and once more per APK at result processing, and the copy turns every read after the first into a small `json.load` plus one SHA-256 of the source. The key is the digest rather than size + mtime so a re-analysed document under the same name is never answered by the old copy; a truncated source is never cached so a recovery cannot shadow a later complete document. A failed write (read-only or full disk) logs a warning naming the copy's path, removes the temporary file and still returns the model. `parse_file(path)` — the producer side's explicit-path read used by `StaticAnalyzer` — streams the file and keeps no copy. No module outside this one references the `.static.json` suffix (`tests/test_static_copy_audit.py`; the definition in `rv_android_core/constants.py` is the permitted match), and the copy is never pushed to a device.
- **The artefact carries its own scope — parsing takes no package key.** GATOR was invoked with `-clientParam codePackage=<key>` and dropped everything outside that key before writing, so `reachability` *is* the application's whole method universe: every entry is loaded, unfiltered, and that set is the coverage denominator (INV-ANA-59). `windows`, by contrast, is **not** scoped by the producer — framework and library activities (`androidx.activity.ComponentActivity`, `com.canhub.cropper.CropImageActivity`) appear there and would inflate the activity denominator — so an `ACTIVITY` window is admitted exactly when its class is present in `reachability` (INV-ANA-60), a test the artefact answers on its own and therefore cannot disagree with the producer. `DIALOG`, `OPTIONSMENU` and other types are admitted unconditionally, because they can be system-provided overlays triggered by app code. No consumption-path function accepts a key (INV-ANA-61): the signatures are `parse_file(path)` and `read_static_analysis_files(results_dir, apk)`. Re-asking the scoping question here could only contradict the producer, and on an app built with `applicationIdSuffix` it would empty the universe outright.
- **Choosing the scope is a production-path concern.** `RVStaticAnalysisConfig.get_tool_command(code_package=…)` emits the `-clientParam`, and `analyze()` records `code_package` / `code_package_source` on its own `StaticAnalysisResult`. The key is the applicationId the APK declares unless the run enabled `PackageDetector` (`--package-detector` / `RV_PACKAGE_DETECTOR`), which elects the implementation package instead — what an app needs whose code lives outside its manifest package (an engine-based game whose classes sit under `org.godotengine.godot`). It is never recovered from a stored JSON: GATOR writes the manifest package into the artefact's `package` member whatever key filtered it, so the run must record its own key (INV-ANA-58).
- **The artefact records its own scope, and the parser reads it back verbatim (INV-ANA-66).** Three members ride beside the manifest `package`: `codePackage` (the key GATOR actually filtered by), `codePackageSource` (`manifest`, `manifest-neutralized` or `detector`) and `class_defs_under_key` (the compiled classes under that key that survive `RvsecAnalysisClient.isAppClass`, counted at write time — a **net** count, never the raw one). `parse_file()` surfaces them as `StaticAnalysisData.code_package` / `.code_package_source` / `.class_defs_under_key`. The producer writes `""` for an unrecorded string and `-1` for an unrecorded count; both become `None`, so *not recorded* stays distinguishable from an empty key or a genuinely zero universe — the state of every artefact written by a producer older than INV-ANA-66. Reading a recorded key is not resolving one, so INV-ANA-61 stands: nothing here filters.
- **Nothing is transformed on the way in (INV-ANA-67).** Class names, window names and signatures are stored exactly as the artefact spells them. Do not rewrite a dot to a `$` between capitalized segments: `SootClass.getName()` writes the JVM binary name, so such a dot is a package boundary, and the other side of the equality test is the raw logcat — a rewrite on one side breaks the match.
- **The chain carries two granularities, and they are different rulers on purpose.**
  A **target** is seeded by class + method name with **no parameters** (`MatchPolicy.LENIENT`,
  INV-ANA-35, `TargetResolver.resolveInScene`), so every overload of a targeted method becomes a
  seed and `reachesTarget` answers a deliberately coarse question. **Coverage** is matched by the
  **complete Soot signature**: `repository_initializer` keys `MethodCoverageData` on
  `method.signature`, and the crossing tests the raw `RVSEC-COV` payload against that key by
  literal equality. So the denominator *does* index by signature and the crossing *does* test by
  signature; reading the target seeding as how coverage is measured would build a denominator
  measurably smaller than the code's. The join key that binds static analysis, coverage and
  violations into one row is the coarse one, `(apk, class, method, spec)`, because the runtime side
  cannot supply more: `rv-monitor` locates a violation from a `StackTraceElement`
  (`Class.method(File:line)`), which carries no parameter descriptor, and `rvsec-core` parses it
  back into `(class, method, loc)`. Coarse where the runtime forces it, fine where the artefact
  allows it: do not key a static↔violation comparison or gate on a full signature.
- **`Loaded N MOP signatures` in the GATOR log is not a target count.** N counts signature-distinct rows, so it is inflated by overloads: `jca` prints **122** while seeding **70** distinct `(class, method)` targets; `jca_android` prints **212** and seeds **115**. Use it to confirm *which spec set* was loaded, never to detect *whether the target set changed* — collapse to distinct `(class, method)` for that. The figures move when a set gains or loses a `.mop`, and also when the client's owner resolution changes without the set changing, so re-measure them whenever either happens. `rv-android/tests/parity/test_gh111_specset_ruler.py` pins the file counts (`jca` 23, `jca_android` 47) and this exact pair.

## Denominator gate (INV-ANA-69)
`check_denominator(classes, compiled_under_key, key)` in `analysis/static/denominator_gate.py` is a pure predicate over the artefact — it divides and nothing more, because `class_defs_under_key` arrives already filtered by the same `isAppClass` that filtered the parsed side. One predicate on both terms is what makes the ratio comparable; the gate holds a count and not the names, so it cannot perform a subtraction of its own. It raises `DenominatorImplausibleError` on three distinct conditions, in this order:

1. **zero compiled universe** (`class_defs_under_key == 0`) — first, and not merely to dodge `ZeroDivisionError`: `0/0` is not a low ratio, it is no ratio, and it is the signature of a key that matches nothing compiled (typically an applicationId carrying a build-type suffix);
2. **empty parsed side** (`reachability` yields no class);
3. **degenerate ratio** (`parsed / compiled_under_key < MIN_PARSED_RATIO`, `0.15`).

`StaticAnalyzer.analyze()` wires it through `_check_denominator()` — the only place holding both the APK and the key, which is why the gate lives there and the parser stays keyless. It costs one extra parse of the artefact. A refusal fails **that APK's** result (`success=False`, message appended to `errors`) instead of propagating: the `ErrorHandler` decorator would swallow a raise and return `None`, which is exactly the silence the gate exists to end, and stopping a whole run for one artefact is not warranted. An artefact recording no `class_defs_under_key` is not judged at all — there is no universe to divide by, and inventing one would be the silent measurement the gate removes.

**A refusal moves the artefact aside, and that is what makes the gate a gate.** Nothing downstream reads the result object: `pre_processor._report_missing_static_analysis` builds its list with `os.path.exists(<apk>.apk.json)` and `result_processor._resolve_static_data` locates the file by name. Left in place, a refused artefact is re-parsed and its collapsed class list published as a percentage with `measured=true` — the outcome INV-ANA-69's own scenario forbids. So `_quarantine_refused_artifact()` renames it to `<apk>.apk.json.refused` (`REFUSED_ARTIFACT_SUFFIX`): the consumers see it as absent and the row takes the honest path that already exists (empty coverage cells, `measured=false` per INV-PLT-35, violation columns written as usual). Renamed and not deleted, because the refusal is a tripwire on a stale `lib/gator/` jar or an unresolved key, and both are diagnosed from the artefact's own recorded key, origin and `class_defs_under_key`.

**Threshold rationale.** With both terms answering to one predicate, a healthy artefact sits at exactly 1.0, and a collapsed one (guard and client reading different keys) falls one to three orders of magnitude below; `0.15` sits inside that gap with a wide margin on both sides. Once the producer-side guard resolves the same key as the client, the degenerate branch is a tripwire on a stale `lib/gator/` jar (client filtering by the new key, guard still running the old) and on any regression of INV-ANA-65 — not a discriminator over healthy apps.

## Cache reuse is keyed (INV-ANA-70)
`_execute_command()` does not treat existence alone as a hit. `_disagreeing_recorded_key()` parses the stored artefact and returns the key it records when that key is not this run's; on a disagreement the file is removed and the analysis re-runs, with a warning naming both keys. `None` — *reuse it* — deliberately covers two cases: an artefact recording **no** key (written by a producer older than INV-ANA-66) and one recording this run's own key. An unreadable artefact is reused too, because the parser recovers truncated JSON on purpose (INV-ANA-06), so a parse failure here says something about the check, not about the file. Without this, a run whose key policy changed would reuse the old artefact and the denominator gate would then judge it by the new key.

`--force` is the *deliberate* invalidation, for a fresh artefact under the same key: `_discard_cached_artifact()` removes `analyzer.analysis_file` before `analyze()` runs. It is declared on both subparsers and honoured by both.

## CLI
```bash
# From rv-android root
uv run rv-static-analysis analyze --apk apks_examples/cryptoapp.apk --output out/sa \
  --mop-dir "$RVSEC_HOME/rvsec/rvsec-mop/src/main/resources/jca_android" --analysis-timeout 1800
uv run rv-static-analysis batch --apks-dir apks_examples --output out/sa --continue-on-error
uv run rv-static-analysis compact app.apk.json app.compact.apk.json
```
`analyze` writes `<output>/<apk>.apk.json`; `batch` writes `<output>/<package_name>/<apk>.apk.json`, analyses sequentially and stops at the first failure unless `--continue-on-error` (`--max-concurrent` is accepted but not read). Exit 0 on success, 1 on any failure.

Flags shared by `analyze` and `batch`:
- `--mop-dir` / `--targets-file` (mutually exclusive, INV-ANA-33) — target source: a `.mop` directory (LENIENT class+name match) or a file of Soot signatures, one per line (STRICT per entry; `..` or `*` params → LENIENT for that entry).
- `--rvsec-root`, `--lib-dir`, `--android-platforms-dir`, `--working-dir`, `--gator-dir`, `--analysis-client-jar` — path overrides.
- `--cg-algorithm` (default `spark`) — call-graph algorithm.
- `--cg-delegation true|false` — passed as `-cgDelegation`; omitted → GATOR's default.
- `--jvm-memory` (default `12g`), `--analysis-timeout <s>` (default 600) — **use these for standalone runs** (see caveat).
- `--skip-wtg` — appends `-clientParam skipWtg=true`; GATOR emits reachability + `windows[]` and returns without building the WTG (`transitions[]` empty). For known-slow APKs where WTG construction is guaranteed to time out.
- `--package-detector` / `--no-package-detector` — which package scopes app-owned classes. Default: the declared applicationId, passed to GATOR as `-clientParam codePackage=` verbatim. Honors `RV_PACKAGE_DETECTOR` under flag > env > default; an unparseable value exits nonzero before any APK is opened.
- `--strip-build-type-suffix` / `--no-strip-build-type-suffix` — neutralize the Gradle build-type suffix of the declared applicationId before using it as the scope key: `com.example.app.debug` becomes `com.example.app`. Default off; honors `RV_STRIP_BUILD_TYPE_SUFFIX` under flag > env > default. The suffix renames the application, not the code, so under the declared id nothing was ever compiled. The denylist is not total, and a key it cannot resolve is caught by the denominator gate rather than silently published. When `--package-detector` is also on the detector wins, and the origin recorded is `detector`, never `manifest-neutralized` (INV-CORE-18).
- `--force` — removes the stored `<apk>.apk.json` before analyzing, so the run regenerates it under the same key. Distinct from the automatic regeneration of INV-ANA-70, which fires only when the key *changed*.
- `--full-output` — sets `full_output`, so GATOR writes the full document: two-space indent, every `targetDistances` pair up to `d = 10`, no `distancePairs`. Use it to reproduce a published document or for an offline analysis that counts pairs beyond the reduction; the pipeline itself never needs it. A cached artefact is reused whatever mode wrote it, so pair `--force` with it to regenerate one.
- `--dry-run` (validate the configuration only), `--summary`, `--verbose/-v`.

### `compact` subcommand (INV-ANA-87)
`rv-static-analysis compact INPUT OUTPUT` (`compact.py`, called by `handle_compact_command`) turns a full-mode document into the compact document GATOR would have written for the same analysis, byte for byte, without running GATOR again — re-analysing a set of APKs costs days, the conversion one streaming pass per document. It reads `INPUT` with `read_analysis_document(INPUT, PairPolicy.reduce(COMPACT_WEIGHED_MAX, COMPACT_K))` from rv-android-core, re-sorts each kept list by target index (the reader yields `(d, i)` order), inserts `distancePairs` before the first of `distanceTargets`/`components`/… the document holds, and serialises with `dumps_gson_compact` — `json.dumps(ensure_ascii=False)` with compact separators plus Gson's escapes of U+2028/U+2029, which `json.dumps` leaves raw. The reduced document is held whole, so memory follows the sections the reduction leaves alone (mostly `windows`), not the input size; the input's text and the dropped pairs are never held.

It refuses with `CompactRefused`, exit 1 and one stderr line naming the input, before any output exists: a truncated input (it is not a document GATOR wrote, so it has no compact form), one already carrying `distancePairs`, one holding a non-integer number (GATOR writes none, and Gson's form of a double is not reproduced), and an `OUTPUT` that is `INPUT` itself. A non-JSON input or an I/O error also exits 1; exit 2 is argparse's usage error. The output is written to a temporary file in `OUTPUT`'s directory, fsynced, given the input's permission bits and renamed onto `OUTPUT`, so an interrupted conversion leaves no file or the previous one. `COMPACT_WEIGHED_MAX`/`COMPACT_K` are pinned equal to `TargetDistances` (Java) and to `aperv-tool`'s `DIST_WEIGHED_MAX`/`DIST_K` by `rv-android/tests/parity/test_distance_pair_constants.py` (INV-ANA-88).

### Standalone env-var caveat
`__main__` is argparse-based, not Click, so it does **not** honor `RV_SA_TIMEOUT` / `RV_JVM_MEMORY` when run directly (`uv run rv-static-analysis ...`). Those env vars only bridge through rv-experiment (`ExperimentConfig.get_static_analysis_config()`). For standalone runs use `--analysis-timeout` / `--jvm-memory`. Architectural fix tracked in `openspec/changes/gh-tbd-env-vars-architecture/`.

`RV_PACKAGE_DETECTOR` and `RV_STRIP_BUILD_TYPE_SUFFIX` are the exceptions, and deliberately so: this command resolves both itself, because a standalone invocation is a run rather than a step inside one, and an operator who exported the variable in a shell or a container should get the same behaviour whichever command they invoke. They are read through the `ENV_PACKAGE_DETECTOR` / `ENV_STRIP_BUILD_TYPE_SUFFIX` constants and parsed by `resolve_bool_setting`, the same helper `rv-experiment` uses, so the two CLIs cannot drift on what a given string means. Both resolve in `main()` before any APK is opened, so an unparseable value exits nonzero immediately.

## Integration seams
- **rv-android-core:** `App`, `StaticAnalysisData`/`Classes`/`Windows`/`WindowTransitionGraph`/`Components`, `EXTENSION_STATIC_ANALYSIS`, `EXTENSION_PARSED_COPY`, `util.analysis_document` (`read_analysis_document`, `PairPolicy`, `digest_of_file`), `resolve_bool_setting`, base analyzer/error/logging infra.
- **rv-experiment:** `PreProcessor._run_static_analysis` calls `analyze()` in pre-processing on the original APKs, writing beside the instrumented ones in `instrumented_apks/`; `app.code_package` is the production key.
- **rv-platform:** runs no analysis — it only re-loads stored artefacts. `StaticAnalysisComponent` and `ResultProcessor` both call `read_static_analysis_files(results_dir, apk)`, passing no key.
- **rv-agent:** consumes `StaticAnalysisData` (not this module's code): WTG → `TransitionManager`/`NavigationGuidance`; MOP flags → `RVAgentVisitor` action prioritization.
- **rv-coverage:** `Classes.methods` is the coverage denominator; `reachable` flag splits reachable vs unreachable.

## Error handling
- `StaticAnalysisException` — execution failures (non-zero exit), **including the defensive post-condition** raised when GATOR returns but no output JSON exists at the expected path (catches a swallowed `CommandNotFoundError` / unreachable launcher, preventing silent zero-coverage downstream). `analyze()` catches it and returns a failed result.
- `DenominatorImplausibleError` — the denominator gate refused the artefact (empty, degenerate, or no compiled universe under the key). Defined in `denominator_gate.py` rather than in `static_analysis.py`, which imports it: the reverse import would close a cycle. `analyze()` catches it and returns a failed `StaticAnalysisResult` naming the parsed count, the compiled count and the key, so the operator can re-run that APK once the jar or the key is corrected.
- `ConfigurationError` (rv-android-core) — invalid config: missing paths, both or neither of `mop_dir`/`targets_file`.
- Parser returns empty sections for missing/malformed data; timeout produces partial JSON whose members written in full the parser keeps (INV-ANA-81).
